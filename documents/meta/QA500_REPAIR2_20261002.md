# QA500 공통 계약 보완 2차 — 실패와 반복 변동 보존

## 결론

원래 3건의 실패를 실제 저장 trace로 재현하고 공통 계약을 수정했다. 그러나 **모델 생성이
모든 반복에서 안정된 상태는 아니다**. 운영 서버·DB·이미지·SSE는 변경하거나 검증하지
않았다. 범위는 실제 Gemma V2 shadow → LogicalProgram → lowering → 공통 synthetic
SQLite runtime → 독립 SQL/oracle이다. V2 derived MineralSet materialization은 이번에도
추가하지 않았고 기존 명시적 미지원 상태를 유지한다.

## 원인별 처리

| 원래 사례 | 최초 손실 지점 | 공통 수정 |
|---|---|---|
| H1 월별 평균/건수 | requested output Project에서 month 삭제 | 다중 그룹 출력의 identity key 검증, alias/qualified key 허용 |
| H4 극값 시점/차이 | Gemma가 source 없는 별도 price requirement 생성 | 명시적 output/relationship 참조와 맞지 않는 unbound requirement를 재계획 오류로 설명 |
| Z5 생산량 평균/건수 | aggregation=mean 뒤 operation=average, value lineage 유실 | 중첩 reduction scope 모호성 및 집계 후 입력 필드 부재를 실행 전에 거절 |

계약 오류 시 기존 최대 1회 semantic repair를 사용한다. Gold나 원문 regex로 node를
주입하지 않는다. 집계 후 또 집계하라는 정당한 질문일 수 있으므로 단순 중복 삭제하지
않으며 현재 requirement로 scope를 표현하지 못하면 명시적으로 거절한다.

감사/실행 중 추가 확인한 공통 오류도 수정했다.

- 집계 후 선택에는 aggregate가 만든 컬럼을 검증한다. 원시 price whitelist로 다시 막지 않는다.
- share는 그룹별 행을 유지하므로 group identity도 유지한다. HHI 같은 scalar는 구분한다.
- runtime의 연산명 처리가 대소문자를 구분하지 않으므로 schema에서도 operation/aggregation을
  strip/casefold한다. `SHARE`로 identity 검증을 우회하는 사례를 회귀에 넣었다.
- 지수 종류가 없는데 `composite_index`를 기본값으로 넣던 V2 lowering을 거절하도록 했다.
  관측 수를 indicator로 잘못 추출한 경우에도 임의 지수로 답하지 않는다.
- 평가기는 기존 광종 alias registry를 재사용한다. `nickel`과 `니켈`은 동등하고
  `nickel`과 `코발트`는 다르다. 신규 alias/Gold 광종 치환은 추가하지 않았다.

## 과적합 방지와 제한

질문별 production 분기 0, 신규 semantic regex 0, 신규 Action/Intent/operator 0.
공통 fixture 데이터와 정답 수치는 변경하지 않았다. 가격 외 생산량·무역, 다른 광종과
기간, 집계→비중 및 scalar 선택 등의 반례를 포함했다. 기존 `qa-build` 절차에 따라
실패 fixture를 먼저 만들었고 수정 전 **8 FAIL / 2 PASS**를 확인했다.

이번 새 regression은 최종 15개다. read-only 독립 감사에서 발견한 scalar 오거절,
share lineage 누락, 대소문자 우회 모두 재현·수정 후 재확인했다.

명시적으로 그룹 키를 숨기라는 요청과 모델의 누락을 현재 schema가 구분하지 못한다.
다중 그룹 출력은 식별 키를 요구한다는 제한을 기록한다. 이 제한에 부딪힌 질문을
무조건 모델 오류로 집계하지 않는다. 중첩 집계 scope 역시 임의로 추정하지 않는다.

registry를 사용한 독립 재판정에서 실제 numeric/date/source 결과까지 통과했다.
원래 실행과 재판정을 각각 보존하며 모델을 재호출하거나 Gold 계획으로 바꾸지 않았다.
새 holdout 질문에 맞춘 prompt/production 튜닝은 하지 않았다.
