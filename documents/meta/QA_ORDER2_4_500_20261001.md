## 수량과 분류

| 난이도 | 질문/시나리오 수 | 연산 패턴 수 |
|---|---:|---:|
| 2차 | 160 | 40 |
| 3차 | 180 | 45 |
| 4차 | 160 | 40 |
| 합계 | 500 | 125 |

500개는 125개 연산 설계 × 4개 광종·기간·국가 조합이다.
500개의 서로 다른 operation graph라는 의미는 아니다. 단순 조사·존댓말 치환이 아니라
동일 계약이 다른 대상·기간에서도 유지되는지 검증하기 위한 parameterized coverage다.
2차는 조회 뒤 하나의 분석 목표, 3차는 복수 중간 결과의 비교·결합,
4차는 선택한 집합·국가·날짜를 후속 조회와 연산에 반복 전달하는 난이도 분류다.
order는 AST node 개수나 턴 수와 같지 않다.

  질문에 따라 아연·알루미늄·흑연·망간을 명시한 집합도 사용한다.

## 검증 범위와 정답 정책

이번 요청은 **질문 생성**이므로 qa-build의 원본 추적·semantic decomposition·등록·
중복 및 무결성 검사를 적용했다. production 기능 구현/500건 Gemma 실행으로 확장하지 않았다.
이 파일의 operation graph는 gold 설계용 개념 연산 흐름이다. runtime에 동일 이름의
primitive가 등록됐다는 뜻이 아니며, 현재 지원 여부는 `NOT_ASSESSED`로 유지한다.

각 항목에는 source_id, pattern_id, order, metric, parameter bindings, operation graph,
expected AST/result invariant, lowering 원칙, 필요 dependency, 독립 turns를 넣었다.
parameter bindings는 변형을 생성한 전체 입력 묶음이다. 개별 문장에 사용되지 않은
변수도 있으므로 이를 파서가 추출해야 할 entity/filter 목록으로 간주하지 않는다.
실제 질문의 요구 범위는 question/turns와 개별 invariant를 함께 읽어 판단한다.
조건부 기권·선택 요청도 정상 기대 동작일 수 있다. 숫자 정답은 만들지 않았다.
`expected_result=null`, parser/backend 실행 여부=false, 결과 상태=`NOT_EXECUTED`다.
표준화된 gold AST의 실행 또는 semantic correctness 통과로 오인해서는 안 된다.

문서 항목은 DOCUMENT_FIXTURE_REQUIRED로 기록했다. PageIndex/OKF 중 어느 backend를
실제로 사용할지는 아직 실행하지 않았으므로 임의 확정하지 않았다. 전망·환율은 외부
source 검증이 추가로 필요하다. dependency 표시만으로 BLOCKED 판정을 하지 않았다.

정적 검사는 총수·ID·원문 중복·필수 메타데이터·멀티턴 보존·TXT/JSON 일치·패턴 등록을
검증한다. 이는 챗봇 질문 응답의 PASS 수가 아니다. 전체 rag_core 회귀 결과는 WORKLOG 참조.
운영 DB, 컨테이너, production parser/runtime은 수정하지 않는다.
