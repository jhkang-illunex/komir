# report_gen — 광물자원가격 통계 확장 6+2층 (2026-08-31)

## 배경
사용자 피드백: "지금 보고서는 이 파일이 가진 정보의 한 층(수준 + 기간별
변화율)만 쓰고 있다. 원본을 직접 돌려봤는데 추가 데이터 없이 지금
파일만으로 뽑히는 게 꽤 많다." — 변동성·추세 위치·분포상 위치·낙폭
국면·재고 해석(항상)과, 비교 광종 입력 시 상대가치·연도별 테이블·
계절성을 요청. "이 파일에 없는 것"(거래량·선물커브·환율·타광종·뉴스,
즉 "왜 올랐는가")은 명시적으로 범위 밖으로 뺐다.

advisor 상담 후 확정한 스코프 확인(AskUserQuestion 2건):
1. 신규 층으로 claim 수가 늘어 절 문장 상한과 충돌할 수 있는 문제 →
   **"섹션 문장 상한 자체를 확대"** 선택.
2. 관측치가 짧아 일부 층(MA250·1년 변동성·계절성 등)을 계산 못 할 때 →
   **"명시적 문장으로 안내"** 선택.

## 2026-08-31 후속 수정(같은 날, 커밋 직후 advisor 재검토로 발견)
1차 구현은 위 2번 결정을 `warnings`(→ `data_quality.warnings`)로
처리했는데, `report_render.py`의 기존 SC-016 결정(2026-08-28)에 따라
이 채널은 **독자 응답에서 항상 제외되고 서버 로그로만 남는다**(로그
문구 자체가 "경고(독자 응답에는 미노출)"). 즉 사용자가 명시적으로
고른 "문장으로 안내"가 조용히 "안 보이는 채널"로 구현됐던 것 — 실제
버그였다. 수정: 생략된 층 이름을 모아 current_position에 문장 1개
(`insufficient_history`)로 합쳐 넣는다(claim 예산은 항상 정확히 1만
쓴다 — 상한 9는 그대로 유지, 계산 근거는 아래 검증 참고). `warnings`는
운영 로그 목적으로 그대로 둔다.

같은 재검토에서 발견한 추가 결함 2건도 같이 고쳤다:
- `annual_return_2026`처럼 해가 중간에 끝난(또는 시작한) 연도가
  "2026년 수익률"로 표기돼 hi/lo 문제와 같은 성격의 "기간 라벨이 실제
  커버리지를 과장"하는 함정이 재현됐다 — 그 해 관측치 날짜 폭이 340일
  미만이면 "2026년(연중) 수익률"로 표기하도록 수정.
- 계절성 "참고용" 경고 게이트가 "관측 연도 수 < 2"였는데, 12~1월을
  걸치는 60일 조회처럼 연도는 2개여도 매 달의 표본은 여전히 1개뿐인
  경우를 놓쳤다 — 진짜 조건인 "월별 표본 수 최댓값 < 2"로 수정.

## 구현 6개 층 (current_position 절, 항상 시도)
`app/analysis/komir_summary.py::calculate_price_summary`에 추가. 계산은
전부 요청 바디의 `observations`(그리고 있으면 `compare_observations`)만
쓴다 — 새 데이터소스 없음(사용자 명시 제약).

| claim id | 내용 | 산식 |
|---|---|---|
| `volatility` | 1개월/3개월/1년 연율화 변동성 | 일별 수익률 표준편차 × √252 × 100. 창별로 실제 관측 기간이 그 창의 60% 미만이면(예: 60일 데이터의 "1년 변동성") 해당 창은 생략 |
| `ma_rsi` | 이동평균 배열(20/60/120/250일 중 계산 가능한 것) + RSI(14) | MA는 단순평균, "정배열"=단기>장기 순서대로 내림차순+현재가≥최단기선, "역배열"=반대, 그 외 "혼조". RSI는 Wilder 14일 스무딩 |
| `percentile_position` | 조회기간 가격분포 백분위 | 현재가 이하 관측치 비율×100(관측치 20건 미만이면 생략) |
| `drawdown` | 조회기간 내 최고가 대비 현재 낙폭 + 최대 하락폭(MDD) 구간 | 러닝피크 대비 낙폭의 최솟값(관측치 2건 미만이면 생략) |
| `inventory_context` | 재고량 백분위 + 가격·재고 동행 비율 | 재고량 있는 관측치 10건 미만이면 생략. "동행 비율"=최근 60거래일 중 가격·재고 등락 부호가 같은 날의 비율(10건 미만이면 생략, 상관계수 대신 이 방식을 씀 — 아래 "용어 회피" 참고) |
| `relative_value` | (비교광종 입력 시만) 가격비율의 조회기간 평균 대비 위치 | 같은 날짜 두 계열 가격비 시계열의 평균 대비 최신 비율 괴리율(20쌍 미만이면 생략) |

## 구현 2개 층 (표, `detailed_metrics`에 항상 계산)
문장(claim)이 아니라 `Metric` 리스트로 넣었다 — `detailed_metrics`는
원래 상한이 없어(`key_metrics`만 8개 상한) 섹션 문장수 계약과 전혀
충돌하지 않는다(advisor 권고, 표는 문장보다 리스크가 낮다는 판단).

- `annual_return_YYYY`: 그 해 첫 관측가→마지막 관측가 수익률
- `seasonality_month_MM`: 그 달의 (연도별) 수익률을 평균한 값 — 관측
  연도가 1개뿐이면 `warnings`에 "참고용" 안내를 별도로 남긴다.

## 데이터 부족 시 처리 — "명시적 안내"를 `warnings`로
문장(claim) 예산을 쓰지 않고 `AdditionalCalculatedSummary.warnings`
(→ `data_quality.warnings`, `summary.py`에서 이미 이 용도로 쓰던 채널)로
안내한다. 근거: claim마다 "데이터 부족" 문장을 별도로 만들면 current_
position 예산(9개)을 그 자체로 잠식해 정작 계산된 층이 밀려날 수 있어서다.

## "추세"·"상관계수" 용어 회피
`summary.py::_FORBIDDEN_SUMMARY_TERMS`에 이미 "추세"·"상관계수"가
있다(다른 페이지 전용 용어가 LLM 출력에 새는 걸 막는 공통 가드) —
그대로 쓰면 LLM 정제 경로가 매번 검증 실패로 규칙기반 폴백에 떨어진다.
그래서 "이동평균 배열"(추세 대신)·"동행 비율"(상관계수 대신)로 우회
표현했다 — `prompts.py::PRICE_SUMMARY_INSTRUCTIONS`에도 이 회피를
명시적으로 지시하는 문구를 추가했다.

## 검증
- import 재확인, `scripts/komis_dump_smoke_test.py` 회귀 395콤보
  mismatch 0(변경 전후 동일).
- 실측 대량 데이터(income_data/komis/komis_01_base_metals.json, 니켈
  6,227행·2002~2026, 알루미늄 673행 비교) 직접 계산 검증 — 6개 층 전부
  정상 산출, current_position claim 9개(설계 상한과 정확히 일치),
  전체 claim 15개(major_changes 5 + core_diagnosis 1 + current_
  position 9), `_refine_with_llm`의 용량 가드(15 ≤ capacity 30) 통과.
- 관측치 60건(짧은 조회기간) 시나리오 — 1년 변동성·MA120/250 자동
  생략, "명시적 안내" warnings 2건 정상 발생, current_position 7개로
  자연스럽게 축소.
- `_validate_llm_summary`에 사람이 흉내낸 LLM 출력(major_changes를
  올바르게 번들링)을 넣어 검증 통과(`None`) 확인 — 새 current_position
  9문장 자체는 계약 위반 없음. 60건 시나리오도 재확인(`insufficient_
  history` claim 포함 8문장, 검증 통과).
- **아직 못 한 것 — 실제 LLM 호출 경로는 0회 검증이다.** 위 검증은
  전부 `llm=None`(규칙기반) 경로 또는 사람이 직접 만든 합성 LLM
  출력이다. `_validate_llm_summary`는 "근거 4개 이상이면 최소 1문장은
  근거 2개를 결합해야 한다"(SC-018)는 전역 규칙이 있는데, 관측치가
  아주 적어 major_changes·current_position 둘 다 근거가 희소해지는
  요청(예: 5~10건)에서는 이 규칙을 만족할 문장이 아예 없어 매번
  폴백할 수 있다 — `price_group`이 정확히 이 패턴으로 "예정된 실패"였던
  전례가 있다. 재배포 후 (1) 긴 계열, (2) 관측치가 아주 적은 계열 두
  경우를 실제 LLM으로 호출해 폴백률·검증 실패 사유를 확인해야 한다.

## 산식 정의 — 확인 필요
사용자가 참고한 원본 계산 스크립트의 정확한 계수를 이 세션은 갖고
있지 않다. 위 표의 산식은 표준 관행(연율화 계수 √252, RSI Wilder
스무딩, MDD=러닝피크 대비 최소값)을 따랐지만 사용자 스크립트와
계수 선택이 다르면 숫자가 어긋날 수 있다 — 실제 라이브 결과를 사용자
스크립트 출력과 대조해 확인이 필요하다.

## 미구현/보류

  다르게 원했다면 알려달라.
