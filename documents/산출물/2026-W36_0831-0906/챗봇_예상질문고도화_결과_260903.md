## 1. 20문항 처리 결과

### ①메뉴안내 (5문항) — 전부 이미 충족, 문구만 정렬

`page_recommend` 모듈(2026-08-28 구현)이 계층경로("KOMIS > A > B")·상세
링크·"바로 이동하시겠어요?" 안내·복수후보 전부 제시를 이미 갖추고 있었다.
실패 문구만 발주처 지정 문구("요청하신 메뉴 경로를 확인하지 못했습니다.
상단 전체메뉴에서 확인해 주십시오.")로 교체.

### ②수치조회 (5문항) — 대체로 충족, 신규 기능 1건

table/image SSE 이벤트(상세표+차트)·출처표기는 기존 구현으로 충족. 신규로
추가한 것: 조회 0건 시 "조회 가능 기간은 YYYY.MM.DD~YYYY.MM.DD입니다"류
안내를 **실제 DB 범위로 동적 생성**(②-1 가격, ②-3 지표 둘 다 — 사용자 결정
"3곳 전부 한번에"에 따라 ④-나까지 같이 적용).

### ③보고서/문서검색 (5문항) — 대체로 충족

RAG(hybrid_search·pageindex)가 문서목록+원문링크+"인과단정금지→동시발생
흐름 서술" 규율을 이미 갖추고 있었음. GDELT 직접조회는 이번 라운드 스코프
제외(§2-4).

### ④예외사항 (6문항) — 5건 처리 + near-miss 구조 문제 발견·수정

| 항목 | 상태 |
|---|---|
| (가) 지원 광종 밖 | 신설 `unsupported_mineral` 사유 + near-miss 우회 버그 수정 |
| (나) 조회기간 데이터 없음 | 동적 가용기간 안내(②와 공유) + 명시적 과거기간 추출 배선 |
| (다) 데이터부족·산출한계 | 기존 구조로 처리(예측모델 자체가 가용 데이터 없으면 결과 미생성 — 변경 없음) |
| (라) 질문 모호 | 문구 정렬 |
| (마) 보안·개인정보 | 신설 `security_privacy` 사유 + 사전분류 게이트 |
| (바) 투자자문 | 신설 `investment_advice` 사유 + 사전분류 게이트(마와 동일 게이트) |

**중요 발견**: near-miss 기능("검증 불충분이어도 근거가 하나라도 있으면
근접매칭 제안")이 dense 검색의 topically-비슷한 결과 때문에 ④예외사항
전부를 정식 기권 분기 대신 근접매칭으로 가로채고 있었다(실측 3건 재현).
(가)는 `komis_resolve_mineral`의 결정적 경고 문구로 근접매칭 후보에서
제외하도록 수정. (마)·(바)는 그런 결정적 신호가 없어 검색 자체를 시작하기
전에 막는 사전분류 LLM 게이트(`_classify_pre_gate`)를 신설(§2-1 결정에 따름,
공유 `ROUTE_PROMPT`는 비변경).

## 2. 설계 질의·결정 기록

작업 중 5가지 설계 충돌/모호점이 발견돼 main-agent를 거쳐 사용자에게
질의했다. 결정 사항:

1. **지원 광종 밖 처리**: "지원 광종 목록" 개념은 유지하되, 2026-09-01
   철폐한 komir 자체산출물(`structured`) 5광종 화이트리스트와는 다른 축임을
   명확히 함 — `komis_resolve_mineral`이 이미 `ai_mnrl_mst`(약 80종) 실조회로
   내는 null 판정을 그대로 쓰고, 새 하드코딩 리스트는 만들지 않음.
2. **public/private 적용범위**: 이 문서의 요구사항은 `/prichat`(private)에만
   적용. `/pubchat`은 기존 게이팅(indicator_market/supply/composite 제외) 유지.
3. **동적 가용기간 안내 범위**: 가격(②-1)·지표(②-3)·일반 기간없음(④-나) 3곳
   전부 이번 라운드에 구현.
4. **아코디언 UI**: 백엔드 데이터 계약(table/image SSE)까지만 이번 스코프,
   UI 접기/펼치기는 streamlit-agent 몫으로 분리.
5. **GDELT 직접조회**: 이번 라운드는 기존 dense/pageindex 커버리지로 충분—
   신규 MCP 도구는 만들지 않음. 향후 별도 라운드에서 기존 geo_event 파생
   데이터가 아닌 새로운 데이터 연동으로 진행 예정(사용자 확인).
6. **마/바(보안·투자자문) 처리 방식**: 공유 `ROUTE_PROMPT`는 건드리지 않고
   별도 사전분류 LLM 호출을 추가하는 쪽으로(턴당 지연 증가를 감수, 최근 여러
   차례 수정된 공유 프롬프트 리스크 회피).
7. **과거기간 추출(④-나) 스코프**: 이번 라운드에 같이 처리(사용자 결정
   "이번에 같이 처리").

## 4. 배포 검증 중 발견한 별도 버그(chatbot-agent 작업과 무관, main-agent가 발견·수정)

재배포 후 라이브 검증 중 "규회석" 케이스가 기대(`unsupported_mineral`)와
다르게 `retrieval_error`로 나오는 걸 발견. 원인 추적 결과
`services/shared/retrieval/pageindex.py`·`pageindex_agent.py`가 inhouse
root 경로를 고정 `parents[3]` 인덱스로 계산하고 있었는데, 이는 소스트리
직접 실행(cwd=inhouse)에서만 맞고 **컨테이너(services/shared→./shared로
평평하게 COPY)에서는 `/`(파일시스템 루트)로 잘못 계산**돼 PageIndex 조회가
컨테이너에서 매번 조용히 실패하고 있었다 — near-miss 우회 로직이 이 실패
경고(`pageindex_failed`)를 결정적 도구실패로 먼저 잡아버리면서 우연히
드러났다. `routers/chat.py`의 기존 `_find_root`(마커 파일을 위로 훑어 찾는)
패턴으로 교체해 소스트리·컨테이너 양쪽에서 정확히 동작하도록 수정.

이 버그는 chatbot-agent의 이번 작업과 무관하게 **컨테이너 배포본에서는
계속 존재해온 잠복 결함**이었을 가능성이 높다(직접 실행/smoke 테스트는
다른 경로 조건이라 안 걸렸던 것으로 추정).
