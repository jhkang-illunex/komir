## 배포 스크립트 검증 기준 점검

배포 스크립트는 `verify_chatbot_changes.sh`의 고정 회귀 검사 후 이미지를 빌드하고,
`verify_live_chatbot.py`의 핵심 라이브 질의를 통과해야 교체한다. 검증 실패 때는 이전
컨테이너를 되돌리는 절차가 있다. 이번 배포 과정에서 라이브 검사 중 일부가 현재 응답
계약보다 오래된 기대를 갖고 있음을 실제 롤백으로 확인했다.

| 검증 기대 | 현재 계약/관측 결과 | 판정 |
|---|---|---|
| 일부 가격 질의는 `done.citations`가 비어야 성공 | 검증된 Action의 근거 citation을 내부 응답 객체에 보존 | 오래된 검사. citation 보존을 확인하도록 수정 |
| 모든 가격 기준이 `LME CASH` | 조회 자료에 따라 니켈은 LME CASH, 구리는 spot 등 서로 다름 | 지나치게 고정된 검사. 실제 응답 기준을 조건부로 확인하도록 수정 |
| KOMIS 원천 메뉴 경로 출처도 표시되면 실패 | 사용자 출력에는 메뉴 경로 출처를 허용하고 DB 테이블명은 숨김 | 오래된 검사. 메뉴 라벨은 허용하고 raw 테이블명 노출만 차단하도록 수정 |
| 상위 수입국 요약 문구가 광물명 바로 뒤에 고정 | 의미는 같아도 기간·기준 설명이 광물명과 순위 사이에 올 수 있음 | 표현에 과민한 검사. 유연한 문장 패턴으로 수정 |
| 단위 코드 `PR001`, `WT002`가 답변에 노출 | 코드 대신 확인된 USD, 톤으로 표시해야 함 | 실제 제품 결함. 응답 코드를 수정해 배포 이미지에 포함 |
| 한국 수입 상위국 응답에 citation이 없을 수 있음 | 성공한 순위 응답은 `trade.country_rank` 출처 citation을 보존해야 함 | 실제 제품 결함. citation 연결을 수정해 배포 이미지에 포함 |

따라서 배포 검사기는 실제 결함을 막는 역할과 함께, 과거 정책을 고정해 정상 응답을
거부할 위험도 있었다. 이번에 확인한 4개 표현/계약 검사는 갱신했지만, 테스트 전체가
데이터 값 변화에 독립적이라는 뜻은 아니다. 가격 기준, citation 정책, 메뉴 출처 표기처럼
응답 계약을 바꿀 때는 배포 게이트 기대도 함께 검토해야 한다.

## 56건 QA의 정답성 재검토

자동 분류는 PASS 33, PARTIAL 9, FAIL 8, BLOCKED_DATA 6이다. PASS는 완료 이벤트와
질문별 기대 표지 중심 판정이라 응답 의미의 정확성이나 필수 필드 완전성을 보증하지 않는다.

자동 PASS 중에도 다음 응답은 보완이 필요하다.

- **MP01**: 니켈 가격·한국 수입국 구성을 함께 요청했지만 가격 요약이 `데이터 없음%`와
  `고점 데이터 없음`으로 출력됐다. 수입국 순위는 정상이어도 가격 Action 결과를 정확히
  처리하지 못한 복합 응답이다.
- **MP03**: 수입 상위국은 제시했지만 함께 요청한 현재 가격의 숫자가 없다.
- **CN08**: 응답에 `monthly_composite_index`, `monthly_trend` 내부 Action 식별자가 노출됐다.

forecast.price 미제공은 다수 질의에서 계속 확인됐다. PF01/PF02는 확인 가능한 실적만
표시하고 예측 자료 부재를 밝혀 임의 전망을 만들지 않았지만, 전망 기능 충족으로 볼 수는
없다. 월간·주간 문서 질의 일부는 `advisor_rejected` 또는 기간 자료 부재로 중단됐다.
IX01/CN09는 public 프로필에서 private-only 지표 접근을 거절했으며, 이는 프로필 정책에
따른 차단이다. REG01은 세계 리튬 수출국 원천 데이터가 없어 기권했다.

전체 QA 판정은 **미수락**이다. 제품 결함, 원천 데이터 부재, 접근 정책 차단, Planner 또는
문서 검색 실패를 서로 다른 후속 작업으로 분리해야 한다. 이 결과는 이미지 교체나 배포
게이트 통과만으로 전체 Q&A 품질이 보증되지 않는다는 사례도 포함한다.
