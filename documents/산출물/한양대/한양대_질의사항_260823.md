## 1. 과업1(위기진단) 관련

1. **경보 단계 표기(4단계 vs 5단계)** — 슬라이드2에 "5단계"로 표기돼 있는데, 과업지시서
   붙임2·화면기획안 v1.3은 모두 「자원안보특별법 시행령」 기준 4단계(관심·주의·경계·심각)를
   명시합니다. 실제 채택 단계 수·명칭·기준을 확인 부탁드립니다(표기 오류인지 실제 5단계
   설계인지).
2. **진단 입력의 미래정보 사용 여부** — Chronos-2의 미래 4주 가격예측치를 진단 판정 입력에
   사용하는 구조로 파악됩니다. 과업지시서 1①의 "현시점 진단(diagnosis), 미래시점 위기
   예측이 아님" 조항과의 정합성을 어떻게 보고 계시는지, 또는 as-of(진단시점까지의 데이터만
   사용)로 조정할 계획이 있으신지 궁금합니다.
3. **검증 범위 확장 계획** — 현재 니켈 1개 광종·특정 시점 스팟체크(2/28·4/11·7/25 등)로
   검증하신 것으로 보입니다. 나머지 4개 광종(CU/LI/CO/REE) 및 연속 기간(워크포워드 등)
   검증 일정을 공유해주실 수 있는지요?
4. **정량 검증지표 도입 계획** — 정답라벨 부재로 QWK 등 정량지표를 아직 제시하지 않으신
   것으로 파악됩니다. 라벨(정답) 확보 방법과 정량지표 도입 계획이 있으신지요?
5. **필수변수 6종 매핑표** — 과업지시서 필수변수(①시장변동성~⑥지정학적리스크) 각각이
   모델의 어느 입력/피처에 대응하는지 명시적 매핑표가 있으신지요? 특히 **④세계공급부족
   (소비/공급)** 대응 데이터원천이 궁금합니다(komir도 이 변수는 아직 미확인 상태입니다).
6. **신규지표 3종 개발 현황** — 공급망압력지수·원자재지수·ESG지수(과업지시서 명시 요구)
   개발 착수 여부와 계획을 공유해주실 수 있는지요? (komir는 원자재지수만 시도 후 라벨오염
   우려로 미채택, 나머지 2종은 미착수 상태입니다.)
7. **후보모델 비교검증 수행 여부** — 과업지시서가 요구하는 "로지스틱회귀·Decision
   Tree·RF 등 다각적 비교검증"을 진단(LLM 직접판정 구조) 쪽에서 수행하셨는지, 혹은 계획이
   있으신지요?
8. **5요인 루브릭 채점 방법** — 지정학 리스크 5요인(사건현실화·공급연결성·실제공급차질·
   지속성·영향범위, 0~4점) 채점이 수동인지 자동(LLM)인지, 동일 사건 반복 채점 시 재현성
   (일관성)을 어떻게 확보하시는지 궁금합니다.
9. **라벨오염 방지 설계** — 가격이격률 등급을 판정 입력에 직접 사용하는 구조로 보이는데,
   타깃(위기등급)과 입력이 동일 원천(가격)에서 파생되며 생길 수 있는 오염 가능성에 대한
   별도 설계적 방지책이 있으신지요? (komir는 가격파생 피처를 주모델에서 의도적으로 제외해
   이 위험을 차단하고 있습니다.)

## 2. 과업2(수요예측) 관련

10. **검증 범위 확장 계획** — 실측 제시된 것은 니켈 1개 광종·수입액·h=1(1개월 후)로
    파악됩니다. 나머지 4개 광종·수입중량(ton)·h2~12 지평 확장 일정을 확인하고 싶습니다.
11. **best-of-3 오라클 수치의 운영 적용 방식** — MAPE 6.96%는 사후 최적선택(오라클) 수치로
    명기하신 것으로 이해했습니다. 실제 운영(배포) 시에는 3후보(VAR/Chronos-2/LLM) 중
    어떤 방식으로 최종 예측치를 사전에 선택하실 계획인지요?
12. **확률 자동산출·시나리오 프레이밍 설계 방향** — 낙관/중립/비관 3분류가 현재 휴리스틱
    이라고 이해했습니다. 확률 자동산출 알고리즘의 설계 방향(통계적 근거)을 공유해주실 수
    있는지요?
13. **앙상블 구성 세부** — VAR의 3변량 구성 변수, Chronos-2 공변량 8종의 구체 목록, LLM이
    결정하는 중심보정치(정광비중·유사월비율 등) 산정 로직을 확인하고 싶습니다.
14. **정성정보(KOMIS 월간보고서 LLM점수 9종) 산정 기준** — 각 점수 항목의 정의·산출
    방식과, 상태벡터(35차원)·중심보정률에 반영되는 가중치/방법을 공유해주실 수 있는지요?

## 3. 공통·방법론

15. **LLM 서빙 환경·GPU 사양** — gemma4:31b의 서빙 방식(양자화 여부·프레임워크)과 GPU
    사양(대수·VRAM)이 확정되면 공유 부탁드립니다. komir 쪽(gemma-4-26b-a4b MoE, fp8)도
    인프라팀 확인 대기 중이라 상호 정렬이 필요합니다.
16. **소표본 강건성 검증** — Chronos-2 zero-shot 방식이 실제 소표본(한국 특정 광종 수입
    데이터) 환경에서 얼마나 안정적인지에 대한 별도 강건성 검증(이웃 강건성·부트스트랩 등)이
    있으신지요?
17. **서술형 근거의 신뢰성 확보 방법** — LLM 자유서술 근거의 환각(할루시네이션) 방지 장치
    (인용 강제·근거 검증 등)가 있으신지요? — komir가 유사 기능(화면기획 #13·#21) 도입을
    검토 중이라 참고하고 싶습니다.

## 5. [신규] 발주처 요구사항 안내 — LLM/임베딩 모델 보안감사

> 아래는 질의가 아니라 **발주처(광해광업공단) 신규 요구사항 전달**입니다 — 양 팀 모두
> 해당되는 사항이라 비교 문건과 함께 공유드립니다.

발주처 측에서 시스템에 사용되는 **언어모델(LLM)·임베딩 모델 등 AI 모델 전반에 대한
보안감사**를 요구했습니다. 핵심 내용:

1. **보안 취약점 보고서 제출 필요** — 구현물에 언어모델(예: Chronos-2, Gemma4 등)을
   사용하는 경우, 해당 모델 각각에 대한 보안 취약점 보고서를 제출해야 합니다(모델
   출처·라이선스·알려진 취약점(CVE)·공급망(가중치 배포 경로) 안전성 등 포함 예상).
2. **"제외 모델" 지정 시 사용 불가** — 감사 결과 특정 모델이 "제외 모델"로 지정될 경우,
   해당 모델은 시스템에서 **사용할 수 없습니다** — 대체 모델로 교체가 필요합니다.

이에 따라 다음을 확인·준비 부탁드립니다:

20. **사용 중인 모델별 보안 취약점 보고서 준비 현황** — 귀 팀 구현물에 쓰인 Chronos-2
    (시계열 파운데이션모델)·Gemma4(LLM) 각각에 대해 보안 취약점 보고서를 보유하고
    계신지, 혹은 준비 계획(작성 주체·일정)이 있으신지요?
21. **제외 모델 지정 시 대체 계획** — 만약 감사 결과 Chronos-2 또는 Gemma4가 "제외
    모델"로 지정될 경우, 사전에 검토해두신 대체 모델(동급 파운데이션모델/LLM)이
    있으신지요?

> **참고(komir 측 현황, 동일 요구사항 적용 대상)**: komir는 LLM `gemma-4-26b-a4b`
> (vLLM, `openai_compat` 어댑터 경유)·임베딩 모델 `intfloat/multilingual-e5-small`
> (sentence-transformers, 로컬 실행)을 사용 중이며, komir 측도 동일 기준으로 보안
> 취약점 보고서 준비 및 제외 모델 지정 시 대체 계획 수립이 필요한 상태입니다. 양 팀이
> 공통으로 대응해야 할 항목으로 판단되어 함께 공유드립니다.
