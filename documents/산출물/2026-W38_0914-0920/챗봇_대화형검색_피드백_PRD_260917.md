## 1. 확인·구현 대상 (우선순위 순)

### 1.1 §5.1 "데이터 부족·산출 한계" 범주 — 신규 (가능성 높음, 우선 확인)

문서: "학습 데이터가 불충분한 경우"(예: 신규 편입 광종 장기 예측) — 응답 예시
"해당 광종은 예측에 필요한 데이터가 충분하지 않아 결과를 제공하지 못합니다. 충분한
데이터 확보 시점은 YYYY년 예정입니다."

- 확인: `chatbot.py`의 `_AbstainReason.reason` Literal(`off_topic·security_privacy·
  investment_advice·prompt_injection·no_data_for_period·ambiguous`)에 이 범주가
  없다 — `no_data_for_period`(조회 **기간**에 데이터 없음)와는 다른 개념(광종 자체가
  **구조적으로** 데이터가 부족·모델 대상이 아님)이다.
- 구현(있어야 한다면): `_AbstainReason.reason`에 `insufficient_training_data` 추가,
  `_ABSTAIN_REASON_PROMPT`에 구분 기준 추가(위 no_data_for_period와 헷갈리지 않게
  — "기간을 바꿔도 안 되는가"가 핵심 구분점), `_abstain_reason_text`에 문구 추가.
  "확보 시점 YYYY년"처럼 구체 연도를 코드가 알 방법이 없다면(현재 그런 메타데이터
  원천 없음) 시점 언급 없이 "충분한 데이터가 확보되면 제공 가능합니다" 정도로
  낮춰 쓴다 — 근거 없는 연도를 만들어내지 않는다(이 프로젝트 전체 원칙).
- 이 범주는 결정적 마커가 없어(신규 광종 여부를 판별할 도구가 마땅치 않음) 실제로는
  LLM 분류(`_classify_abstain`)에 맡기는 선에서 그친다 — 결정적 코드 검출까지는
  범위 밖으로 판단되면 문서화하고 넘어갈 것.

### 1.2 §3.2 수입국 비중 — 분자·분모 명시

"비중 계산 시 분자와 분모를 명시하여 투명성을 확보합니다."

- 확인: `komis_raw_lookup`(domestic_trade/global_trade topic)이 만드는 Evidence.text
  또는 근거 표에 비중(%) 계산 기준(예: "해당 연도 총 수입액 대비")이 명시되는지
  `rag_core/ragkit/_mcp_tools_common.py` 확인.
- 없으면: 비중 컬럼이 있는 komis_raw 표의 caveat 또는 section 텍스트에 "전체 대비
  비중(분모: 해당 연도 총 수입액/총 수입량)" 한 줄 추가. mnrl_report의 HHI/편중도
  계산부(`rules/mnrl.py`)가 이미 "전체 대비" 기준을 문장에 명시하는 패턴을 쓰므로
  그 표현 방식을 참고.

### 1.3 §6.3 시계열 기본 범위(1~3개월) 초과 시 안내

"기본 시계열 제공 범위는 1~3개월... 3개월 이상 요청 시 기간 재지정 안내 또는
조회 가능한 최대 범위를 명시."

- 확인: `chatbot_graph.py`의 `komis_relative_months`/`_relative_period_bounds`가
  사용자가 6개월·1년을 요청하면 그대로 다 조회하는지, 아니면 3개월로 자르고
  안내하는지. 현재 동작(어제 실측)은 최신 5건만 반환하며 "요청한 전체 기간이 아닐
  수 있음" caveat만 붙는다 — **개월 수 상한이 아니라 행 수 상한**이라 문서 요구와
  결이 다르다.
- 판단 필요: 이건 데이터 원천(KOMIS API)의 페이지네이션 제약일 가능성이 커서
  "3개월 상한을 코드가 강제"가 아니라 "실제로 몇 건까지 나오는지 caveat로
  투명하게 알리는" 현재 방식이 사용자 경험상 더 나을 수 있다 — **임의로 3개월
  상한 로직을 새로 만들지 말고**, 현재 caveat 문구가 "조회 가능한 최대 범위"를
  구체적으로 명시하는지만 다듬는다(예: "최근 N건(YYYY-MM-DD~YYYY-MM-DD)만
  제공됨" 형태로 실제 범위를 항상 못박기).

### 1.4 §4.3 인과관계 "(시점)↔(시점)" 표기

- 확인: `CHATBOT_SYSTEM_PROMPT`가 인과 단정을 금지하는 규칙은 있는지(대개
  "~때문에" 등 인과 접속 금지 규칙) 문서가 요구하는 "A(시점) ↔ B(시점)" 병렬
  표기 형식까지 명시하는지.
- 가벼운 프롬프트 문구 추가로 충분 — "지표 변화와 문서 근거를 동시에 제시할 때는
  각각에 시점을 붙여 '(사건, 시점) ↔ (지표변화, 시점)'처럼 병렬 표기하고 인과
  접속사를 쓰지 않는다" 한 줄 추가 검토.

### 1.5 §2 메뉴안내 — 별도 서브시스템, 범위 확인만

`intent.py`(document/page 라우팅) → page인 경우 `rag_chat/app/`의 page_recommend가
처리(`search/graph.py` 계열, 이번 세션에서 다루지 않은 영역). 문서 요구사항
(계층 경로 텍스트, 클릭 링크, "바로 이동하시겠어요?" 유도문구, 복수 후보 제시,
경로 불명 시 안내문)이 이미 있는지 해당 모듈만 확인 — 여기서 갭이 나오면 그때
구현. intent.py 자체는 2026-08-28 라운드1~4로 이미 여러 번 정밀 조정됐으니
라우팅 기준(page vs document) 자체는 건드리지 말 것(재발명 금지).

## 2. 검증 절차 (기존 세션 관례 그대로)

1. 코드 확인 후 §1 각 항목이 실제 갭인지 먼저 판정 — 이미 충족된 항목은 "확인함,
   변경 없음"으로 기록하고 넘어간다.
2. 변경한 항목만 최소 구현.
3. `python -m unittest discover -s rag_chat/tests`(있는 것) 통과 확인.
4. 라이브 검증: `docker build -f inhouse/rag_chat/Containerfile -t komir-rag-chat:
   <날짜-태그> inhouse/` → 기존 컨테이너와 동일 env/mount/port로 교체(어제
   `komir-rag-chat-test` 교체 절차 참고) → 문서 §2~§5 예시 질문 중 이번에 손댄
   항목에 해당하는 실제 질문으로 curl 재현(`/pubchat`, user_id 필수 필드).
5. `documents/meta/WORKLOG.md` 최상단에 항목 추가(원인·수정·검증 결과, 이미
   구현돼 있어 손대지 않은 항목도 "확인함" 한 줄로 남길 것 — 다음 세션이 또
   확인하지 않게).
6. 커밋 메시지는 이 세션 컨벤션(Co-Authored-By 포함)을 따르되, **push는 하지
   않는다** — 사용자가 별도로 지시할 것.
