## 1. 한 줄 요약

주 1회 스케줄러가 RDB 원장을 읽어 두 보고서 테이블(`ai_rpt_overall`·`ai_rpt_mnrl`)의 텍스트
섹션을 채운다. 문장은 **규칙 엔진**(결정론)과 **생성형 엔진**(LLM, 옵션)이 만들고, 두 엔진은
각각 `YYMMDD-sha8` 버전을 가지며 그 버전이 보고서 행마다 기록된다. 사람이 검수해
DRAFT→REVIEWED→DONE으로 확정한다.

## 2. 왜 파이프라인과 엔진을 분리했나

첫 구현은 "읽고→문장 만들고→저장"이 `run.py` 한 흐름에 있었다. 사용자 지적: "이건 rule 엔진이
아니라 데이터를 읽고 저장하는 pipeline". 분리한 뒤 얻는 것은 세 가지다.

1. **추적성**: 보고서 행의 `rule_ver`/`llm_model_ver`만 보면 어느 규칙 코드·프롬프트·모델이
   그 문장을 만들었는지 역추적된다(등록부 `ai_rpt_engine_ver`, 실행 로그 `ai_rpt_gen_run`).
2. **교체 가능성**: 규칙 엔진은 그대로 두고 생성형 엔진만 켜고 끄거나 모델을 바꿀 수 있다.
   모델을 바꾸면 버전이 바뀌므로 "어느 모델 시절 문장인지"가 남는다.
3. **검증 지점**: 엔진이 `EngineResult`(채운 컬럼·근거·폐기 컬럼과 사유)를 돌려주므로
   파이프라인은 판단하지 않고 기록만 한다.

```
원장(public ko_*/ai_*) ─sources.py─▶ facts ─▶ RuleEngine.generate ─▶ RULE 컬럼 ─┐
                                                 │ 근거 = RULE 문장·수치(+뉴스)        ├─ writer.upsert ─▶ ai_rpt_*
                                   (--llm) GenEngine.generate ─▶ LLM 컬럼 ─────────┘   rule_ver/llm_model_ver 기록
   registry.register(engine) ─▶ ai_rpt_engine_ver     registry.log_run(...) ─▶ ai_rpt_gen_run
                                                       검수 화면(사람): DRAFT → REVIEWED → DONE
```

## 3. 컬럼 정책 — 누가 어느 컬럼을 쓰는가

테이블 COMMENT의 [RULE]/[LLM]/[MANUAL] 태그는 계약이고, 실제 동작은 `policy.py`의 컬럼
정책 레지스트리(전체 45·광종 42 컬럼 전수, 테스트가 검사)와 덮어쓰기 규칙이 정한다.

| 정책 | 쓰는 주체 | 덮어쓰기 규칙 |
|---|---|---|
| RULE | RuleEngine | 매 실행 재계산. 행이 DRAFT일 때만(REVIEWED/DONE은 `--force` 없이 불변). 원천이 사라지면 NULL로 덮어씀 |
| LLM | GenEngine(`--llm` 또는 `MNRL_REPORT_LLM_ENABLED=1`) | 실행했을 때만, DRAFT일 때만. 검증 실패 컬럼은 NULL |
| MANUAL | 담당자 | 엔진은 절대 덮어쓰지 않음. 행 최초 INSERT 때 `resources/fixed_texts.json` 시드만 |
| META | 파이프라인/검수 화면 | rule_ver·llm_model_ver·llm_refined_yn / gen_stts_cd·reviewer_* |

원칙: **지어내지 않는다**(원천 없으면 NULL, 광종에 원천이 하나도 없으면 행 미생성),
**더미 불인정**(`ai_dev_dummy_load`·`DEV_DUMMY` 행은 원천으로 쓰지 않음), **미확정 산식은
계산하지 않음**(가격이격률·가격신호), **근거 스냅샷 보존**(`data_lake/mnrl_report/facts_*.json`).

## 4. 규칙 엔진 (RuleEngine, engine_cd=`rule`)

- 본체: `rules/mnrl.py`(광종별 B 섹션), `rules/overall.py`(전체 A 섹션), `rules/fmt.py`(단위·
  서식). 임계값은 `.env`(`MNRL_REPORT_HHI_HIGH` 2500, `MNRL_REPORT_OVERALL_HIGH` 60 등),
  등급 코드·한글명은 `config.py`.
- 버전 해시 입력: rules 3종 + `policy.py` + `config.py`의 파일 내용.
- 문장 규칙은 파이썬 코드에 있다(하드코딩). 판단 근거는 §9.

## 5. 생성형 엔진 (GenEngine, engine_cd=`gen`)

- 근거는 **규칙 엔진 결과(RULE 문장 + 수치 evidence)와 뉴스 제목**뿐. 원장 JSON은 주지 않는다.
- 컬럼별 지시문은 `engines/prompts/ai_rpt_{mnrl,overall}.md`의 `## <컬럼>` 절. 정책 LLM
  컬럼과 1:1(테스트가 검사). 컬럼마다 1회 호출, 평문 출력.
- 버전 해시 입력: `gen_engine.py` + 프롬프트 2종 + `LLM_PROVIDER:LLM_MODEL`.
- `[needs:news]` 게이팅: 원인·사건을 서술하는 컬럼(요약 원인, 주요 내용, 가격 전환 배경, 판단
  근거, 리스크 ①③ 제목·서술, 리스크 ② 해석)은 뉴스 근거가 없으면 **호출 자체를 생략**하고
  `no_news_evidence`로 폐기한다. 수치만 보고 원인을 짓지 못하게 하는 장치다. 현재 뉴스 원천이
  미연결이라 이 컬럼들은 전부 NULL이다.

### 5.1 출력 검증 규칙 (전부 실측에서 나온 것)

| 규칙 | 폐기 사유 코드 | 실측 계기 |
|---|---|---|
| 빈 출력, `(없음)` 포함 | `empty` | 모델이 문장 안에 "(없음)"을 섞어 "…정보는 ." 잔해가 남음 |
| 근거 밖 숫자(연도·월·주차·개수 표기 제외) | `number_not_in_evidence(n)` | 처음엔 "`25년"·"3개국"까지 걸려 정상 문장이 통째로 폐기됨 |
| 근거와 반대 방향어 | `direction_mismatch(n)` | 근거 "4.61% 상승"을 "4.61% 하락"으로 옮긴 사례 |
| "정보가 없습니다"류 메타 문장 | `meta_no_info_sentence` | "산업 수요 배경에 대한 정보가 없습니다"를 보고서 문장으로 내놓음 |
| 빈 자리표시자 | `empty_placeholder` | "공급측면에서 가 주요 원인", "[원인 ]", "원인은 입니다", "정보는 ." |
| 단정 금지어(반드시·확실히 등) | `forbidden_phrase` | 설계 시 선제 적용 |
| 길이 초과(제목 60자, 본문 600자) | `too_long` | 설계 시 선제 적용 |
| LLM 호출 실패 | `llm_error:<예외>` | 호스트 실행 시 LLM 주소 문제(§8) |

추가로, 공용 LLM 클라이언트는 `json_mode=True`가 기본이라 `{"컬럼": "…"}` 껍데기가 그대로
저장되는 것을 실측했다. GenEngine은 `json_mode=False`로 쓰고, 그래도 오는 JSON·코드펜스는
`unwrap`이 벗긴다.

## 6. 버전 체계 — `YYMMDD-sha8`

- **sha8**: 엔진을 구성하는 파일 내용을 정렬해 이어붙인 sha256 앞 8자리(+모델명). 규칙 문구
  한 줄, 프롬프트 한 줄, 모델명 하나만 바뀌어도 바뀐다. 손으로 올리는 버전 상수는 없다.
- **YYMMDD**: 파일 최종 변경일 중 최댓값. 커밋된 깨끗한 파일은 git 커밋일, 미커밋·미추적
  파일은 mtime. 처음엔 mtime만 썼는데 새로 clone한 서버에선 같은 코드가 다른 날짜로 등록되는
  함정이 있어 고쳤다. git이 없는 컨테이너는 mtime 폴백이며 호스트와 같은 버전이 나오는 것을
  확인했다.
- 길이 15자로 `rule_ver`/`llm_model_ver` varchar(30) 안에 든다.

### 6.1 보조 테이블 2종 (이 모듈이 소유, IF NOT EXISTS로 생성)

**public.ai_rpt_engine_ver** — 엔진 버전 등록부. PK (engine_cd, ver).
engine_type(RULE|GEN), ver_date, ver_sha, model_nm(GEN의 모델명), src_files(해시에 넣은
파일 목록 JSON), frst_reg_dt.

**public.ai_rpt_gen_run** — 행 생성 실행 로그. PK run_sn.
base_ymd, tbl_nm, row_key, engine_cd, engine_ver, write_stts(inserted|updated|skipped(not
DRAFT)|dry-run|error), cols_filled, cols_dropped, dropped_json({컬럼: 사유}), facts_path,
started_dt, finished_dt, err_msg. 보고서 행 1건마다 엔진별 1행.

역추적 예시:
```sql
-- 이 행은 어느 버전이 만들었나
SELECT mnrknd_unq_cd, base_ymd, rule_ver, llm_model_ver, llm_refined_yn, gen_stts_cd FROM public.ai_rpt_mnrl;
-- 그 버전은 어느 파일·모델인가
SELECT * FROM public.ai_rpt_engine_ver WHERE ver IN ('260915-d7339d7b','260915-b0efce44');
-- 생성형 엔진이 무엇을 왜 폐기했나
SELECT tbl_nm, row_key, cols_filled, dropped_json FROM public.ai_rpt_gen_run
 WHERE engine_cd='gen' AND base_ymd='20260615' ORDER BY run_sn DESC;
```

### 7.1 생성형 엔진이 드러낸 규칙 엔진 버그 2건 (수정 완료)

LLM이 규칙 문장을 충실히 옮기다 보니 규칙 쪽 오류가 그대로 드러났다.

1. 전체 요약 문장(`smry_quant_txt`)이 첫 광종의 방향어를 모든 광종에 적용했다. 주석은 4.61%
   상승인데 "알루미늄과 주석 … 각각 4.8%, 4.61%의 하락세"로 나왔다. 방향이 다르면 광종마다
   방향어를 붙이도록 고쳤다.
2. 가격 문장(`risk2_quant_txt`)이 전주 방향을 전월·전년에도 일괄 적용했다. 알루미늄은 전주·
   전월 하락, 전년 상승이었다. 기간마다 방향어를 붙이도록 고쳤다.

이 수정으로 규칙 버전이 260915-09133a4f에서 260915-d7339d7b로 자동 상승했다.

- 호스트에서 `--llm`을 쓰면 `common/config`가 저장소 루트 `.env`(컨테이너용 `host.docker.

- vLLM은 temperature 0이어도 호출마다 문장이 흔들린다(2026-09-13 실측). 그래서 근거·버전·
  폐기 사유를 반드시 남기고, 채택은 검수가 정한다.
- `common/db.py`의 public 쓰기 금지 원칙에 대한 예외는 이 모듈의 `db.WRITABLE_TABLES` 4종
  (보고서 2 + 보조 2)뿐이다(사용자 승인, 2026-09-15).
- dataclass 기본값에 `os.getenv`를 쓰면 import 시점에 고정돼 CLI가 넣은 env가 무시된다.
  `get_config()` 호출 시 읽도록 돼 있다.

## 9. 판단 기록 — 규칙을 코드에 둘 것인가, 템플릿 파일로 뺄 것인가

문장 규칙은 파이썬에 하드코딩돼 있다. 문장 틀만 YAML로 빼는 중간 단계도 가능하지만,
유지보수 우위가 월등하지는 않다고 판단해 현행 유지한다.

- 문구만 바꾸는 유지보수는 템플릿이 유리하다. 그러나 이 프로젝트에서 문구를 고치는 사람은
  개발자이고, 발주처 요청은 대개 분기 변경(수치 추가·조건부 절)을 동반했다.
- 분기·서식 변경은 코드가 유리하다. 보고서 문장 87개 중 절반 이상이 조건 분기를 가지며,
  템플릿에 조건 문법을 넣으면 코드보다 읽기 어렵고 테스트도 붙이기 어렵다.
- 추적성·검증은 두 방식이 같다(버전 해시·단위 테스트).

문구 수정 요청이 반복돼 실제 병목이 되면 그때 문장 틀만 빼도 늦지 않다. 그 파일도 버전
해시에 넣으면 추적은 유지된다.

## 10. 남은 결정·후속

| 항목 | 상태 |
|---|---|
| 뉴스 원천 연결(`run.py` ctx `"news"`) | 미착수. 연결되면 `[needs:news]` 컬럼이 생성되기 시작 |
| 진단 지수 실값 원천(`ai_mnrl_diag`·`ai_dash_diag` 더미 해소) | 발주처·타 팀 확인 필요 |
| 가격이격률·가격신호 산식·임계 | 발주처 확정 대기 |
| 5광종 원장 실샘플(주간가격은 동·니켈뿐, 관세청·USGS는 5광종 전부 더미) | 데이터 적재 대기 — 이것이 채워져야 광종별 보고서가 의미 있음 |
| 고정 문안(`fixed_texts.json`) 확정 | 발주처 확정 대기 |
| 검수 화면 연동(gen_stts_cd 전이) | 프론트 팀 |
| 시험 실행 누적 로그 정리 | 사용자 결정 |
| 코드·문서 커밋 | 사용자 지시 대기 |
