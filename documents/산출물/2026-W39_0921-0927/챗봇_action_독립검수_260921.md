## 구현 후 판정

### 1차 개별 감사: `action_contract.py` 초안

- `menu.navigate(target_page='광물지도')`가 `unsupported_action`으로 거절됐다. `dataset.navigate`도 `AVAILABLE`에 없으므로 동일하다.
- `price.series(mineral='니켈', Period(kind='latest', future_horizon=12))`가 `approved=True`였다. 기간 종류 간 상호배제 검증이 불완전하다.
- 두 `price.series`가 `r1→r2→r1`로 서로 의존하는 계획이 `approved=True`였다. DAG 순환 검증이 없다.
- `ActionSlots`에는 가격 기준·통화·단위·비교 창, claim 연산자, 국가 범위, 원자료 dataset 등의 설계 슬롯이 없다. `extra=forbid` 때문에 해당 조건을 타입 있는 값으로 전달할 수 없다.
- 같은 action ID의 복수 요구는 `len(action_ids)>1` 검사에서 조합 검증을 건너뛴다. Q11·Q29 같은 허용 조합도 요구별 기간·척도 관계를 별도로 확인해야 한다.

위 세 실행 재현은 `ActionPlan` 생성 후 `validate_action_plan`의 결과를 직접 확인했다. Terra에 수정 요청했다. 기존 실패를 단순히 무시하지 않고 새 계약으로 재작성된 테스트와 실제 요청으로 대조한다. 미검증 항목은 통과로 판정하지 않는다.

### 2차 개별 감사: call 실행 경로

- Terra가 `depends_on` 순환 검출, 복수 ActionCall의 개별 adapter 호출·Evidence 귀속, Q29의 질문 문자열 연도 정규식 제거, 별도 source 분류 선분기 제거를 반영했다. 코드상 변경을 확인했으며 실요청 검증은 아직이다.
- `action_contract.py`의 `latest` 외 기간 종류는 `future_horizon`과 동시 지정돼도 승인될 수 있다. `Period(kind='trailing_months', trailing_months=12, future_horizon=3)`가 예다.
- `menu.navigate`/`dataset.navigate`는 action ID만 있고 app 메뉴 레지스트리 어댑터로 연결되지 않았다. `/pubchat`의 페이지 경로와 action 경로도 별개다.
- 문서 검색 adapter는 검증된 `topic` 대신 route의 `resolved_query`에 원문 전체를 넣는다.
- Advisor에는 action별 요청 조건과 Evidence의 단위·관측범위·모집단을 비교하는 결정적 필수 필드 검증이 없다. LLM 검증 payload도 해당 메타데이터가 빠져 있다.
- `action_plan_failed:*`와 `advisor_rejected`는 `chatbot.py::_resolve_abstain`에서 안정적 실패 코드로 해석되지 않고 LLM 사유 분류로 넘어간다. 상태 4단계와 조회실패 상태도 실제 SSE로 재검증해야 한다.
- `Evidence` 추적키가 `done.citations`와 근거 패널까지 전달되지 않는다. 문서 발행일·원문 링크 필드도 Evidence 계약에 없다.

중간 회귀: `rag_core/tests` 31개 중 8개 실패(초기 7개와 폐기한 verifier fast-pass를 기대하는 구 테스트 1개), `rag_chat/tests` 62개 중 5개 실패. 신규 `test_action_contract.py` 3개는 통과했지만 앞선 결함을 검사하지 않는다.

### 독립 계약 테스트

`python3 -m unittest inhouse.rag_core.tests.test_action_contract_audit -v`: 6개 중 3개 실패. Q02 광종별 종합지수 차단, Q06 비교 창 전달, 기간 상호배제, DAG 순환 검사는 통과했다. 설계상 available인 `price.verify_claim`(Q28), `menu.navigate`, `dataset.navigate`가 `validate_action_plan`에서 거절되어 실패했다. Terra는 세 기능을 현재 미지원으로 유지한다고 밝혔으므로 설계와 기존 요구를 기준으로 한 합격 판정은 불가하다. 테스트 파일은 `inhouse/rag_core/tests/test_action_contract_audit.py`다.

후속 코드 반영 뒤 위 독립 테스트와 Terra의 `test_action_contract`를 합쳐 **11/11 통과**했다. 세 action은 이제 catalog에서 승인되고 Q28 claim 슬롯은 route까지 보존된다. 하지만 claim 필드는 route의 선언·할당 외 읽는 실행 코드가 없어 300% 전제의 계산·대조가 수행되지 않는다. `menu.navigate`/`dataset.navigate`도 core 호출 시 `adapter_unavailable`이며 기존 app `page_recommend` 경로와의 통합 또는 실제 `/pubchat` 동작은 아직 검증되지 않았다. 따라서 11/11은 타입·초기 라우팅 검사 통과일 뿐 전체 설계 통과가 아니다.

이후 Terra가 Q28 원천 비교값 검사와 대상 광종 필터, 전제가 거짓인 경우의 Evidence 보존을 추가했다. 실패 조회에는 stage 3 `조회실패`와 `failure_reason`을 송신한다. 코드상 변경을 확인했으며 테스트 이미지 실요청은 아직이다.

독립 Advisor 반례 테스트를 추가했다. `price.series(니켈, 2025년 명시)`와 `observed_period=2023-01-01~2023-12-31`인 Evidence를 주고 모의 LLM이 `sufficient=True`로 승인하면 `_verify_node`도 `sufficient=True`를 반환한다. `python3 -m unittest inhouse.rag_core.tests.test_action_contract_audit -v`는 7개 중 이 사례 1개 실패했다. 결정적 기간 적합성 검증이 필요하다.

Terra가 명시 연도의 다른 연도 근거를 차단하도록 수정해 이 반례는 통과했다. 추가한 단위·광종 반례에서는 여전히 `USD/톤` 요청에 `CNY/kg` 근거, 니켈 요청에 코발트 표 근거가 모의 LLM 승인만으로 통과했다. 부분기간은 설계상 실제 관측범위와 결측을 안내하며 답할 수 있어 차단 테스트로 삼지 않았다. 독립 테스트 10개 중 단위·광종 2개 실패가 남았다.

app 진입 경로는 ActionPlan 선추출 실패에 fail-closed SSE를 보내도록 바뀌었다. 명시 mode와 action 유형 충돌도 `mode_action_conflict`로 처리한다. 추출 예외·계약 실패·mode 충돌의 user/assistant 세션 저장과 delta 안내를 정적으로 확인했고 `py_compile`이 통과했다. menu/dataset의 typed slot을 검증된 페이지 레지스트리에 전달하는 adapter는 아직 구현 중이다.

후속 Advisor 수정 뒤 독립 반례 테스트 **10/10 통과**. 단위 `USD/톤` 대 `CNY/kg`, 니켈 대 코발트 표, 명시 2025년 대 2023년 근거가 LLM 승인 전에 거절됨을 확인했다. 광종 검사는 markdown 표에 `mineral` 열이 있을 때, 기간 검사는 현재 연도 문자열 범위에 한정된다. 실제 기간·결측 안내와 인용은 테스트 이미지 요청으로 확인해야 한다.

typed page adapter가 추가돼 `광물지도`·`수급동향지표` 자연어 명칭이 등록 페이지와 링크로 해소되고, 답변에 `KOMIS > ...`와 이동 질문이 들어간다. 그러나 기존 유형6에 가까운 `dataset='니켈 수급동향지표 전체 데이터'`는 `RegistryError unknown page_id`이며 니켈 필터도 전달되지 않는다. 독립 `test_action_page_adapter_audit.py` 4개 중 이 사례 1개 오류. 모호 메뉴의 복수 후보도 현재 단일 `registry.get` 오류로 처리된다.

이후 dataset은 자유 문구 대신 `supply_stability`·`market_outlook` 공식 ID와 별도 `mineral` 슬롯을 받도록 바뀌었다. 독립 page 테스트를 이 계약에 맞춰 갱신했고 **4/4 통과**했다. 복수 후보는 `resolve_action_targets`가 exact label 중복일 때 목록을 만들 수 있으나 실제 모호 메뉴 질문의 복수 후보 실요청은 아직 확인하지 않았다.

남은 전체 단위 테스트는 구 경로 모의 기대와 분리해 판정한다. `rag_chat/tests/test_retrieval_routing.py` 5개 실패 중 4개는 typed plan 없이 `_retrieve_node`를 직접 호출한 HHI·명시 HS·광종별 종합지수·private 경계 테스트이며 새 plan을 주입해 같은 기능을 재검증해야 한다. 나머지 1개는 설계상 폐기할 invalid-route regex fallback을 기대한다. `rag_core/tests/test_internal_knowledge_route.py`의 `assess_source_request` 기대는 폐기된 원천 분류 계약이고, Q21 모의 테스트는 현재 분류 호출을 차단하지 않아 12초 timeout이 난다. 이들은 live 결과와 별도로 갱신해야 하며 무조건 통과로 취급하지 않는다.
