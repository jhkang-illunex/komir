## 현재 구조 판단

현재의 큰 흐름은 유지한다.

`rag_chat` → `rag_core`의 의도 분석·ActionPlan·근거 검증 → 조건부 RDB·pgvector·PageIndex 조회 → OKF 원문 확인 → SSE 응답

RDB, pgvector, PageIndex는 ActionPlan이 필요로 할 때 병렬 조회한다. OKF는 네 번째 독립 검색원이 아니라 PDF·HWP·Excel에서 정제한 문서 원문과 메타데이터의 기준본이며, PageIndex 탐색 결과의 본문 검증에 사용한다.

## 반영 상태

| 항목 | 상태 | 구현 내용 |
|---|---|---|
| 메뉴 기준 출처 표시 | 완료 | `menu_data_catelog.yml`의 3개 주메뉴·11개 하위 메뉴를 RDB 원자료와 결정적 집계 도구의 `Evidence.menu_page_id`에 연결했다. 단일 메뉴를 확정할 수 없는 광종 간 가격 비교는 원천 테이블 출처를 유지한다. |
| 무역지수 HITL | 완료 | TSI·RCA·TII·수출입 증감률·특정국 의존도 요청에서만, 자연어로 빠진 지표별 필수 슬롯을 묻는다. 다른 질의의 추가 질문 범위를 넓히지 않는다. |
| OCR 후 PageIndex freshness | 완료 | PageIndex 트리에 OKF 본문 SHA-256을 기록하고, OCR 재처리로 본문이 달라지면 기존 트리를 stale로 판정해 다시 만든다. checksum이 없는 기존 트리도 한 번 재생성한다. 프론트매터만 바뀐 경우에는 기존 메타데이터 동기화를 유지한다. |
| ingest 체인 실패 전파 | 완료 | PageIndex·backfill·prune 같은 후속 단계는 가능한 다음 단계를 계속 실행해 상태를 남기되, 하나라도 실패하면 `chain.run_chain`을 실패로 기록하고 종료 코드 1을 반환한다. |
| RCA·TII 세계 분모 데이터 | 배선 대기 | 계산식·MCP·슬롯 검증은 준비됐으며, 세계 교역 분모를 제공할 데이터 계약 어댑터 연결이 남았다. |
| `evidence_status`·`no_evidence` 외부 계약 | 협의 필요 | 답변 불가 플래그의 소비 주체와 표시 규칙을 현호님과 합의한 뒤 추가한다. |

## 코드·모듈 보완 후보

| 우선순위 | 대상 | 보완 내용 | 적용 범위와 이유 |
|---|---|---|---|
| 높음 | `rag_chat/app/routers/chat.py` | HITL의 상태 보관·SSE 이벤트 포맷만 공통 함수로 추출 | 무역지수의 누락 슬롯 HITL과 광산의 기존 추가 질문을 같은 동작으로 합치지 않는다. 기능 적용 대상은 늘리지 않고, 라우터 분기 중복만 줄이는 후보이다. |
| 높음 | `rag_core/ragkit/chatbot_graph.py` | Action별 `RetrievalRoute` 필드와 MCP 호출을 레지스트리 기반 어댑터로 단계 분리 | 라우트 플래그와 도구 분기가 증가할 때 변경 범위를 좁힌다. 현재 기능 마감 전에는 동작 변경 없이 작은 단위로 검증해야 한다. |
| 중간 | `rag_core/ragkit/chatbot_graph.py` | 문자열 경고 `source_audit:*`를 typed 결과 객체로 교체 | 문자열 파싱이 키 변경 때 조용히 깨지는 위험을 제거한다. |
| 낮음 | `common/komis_raw.py` | 세계 교역 분모 어댑터를 별도 모듈로 옮기고 데이터 계약 검증을 독립 | RCA·TII 원천을 연결할 때 RDB 조회 책임과 외부 분모 계약을 분리한다. |

## 운영 확인 항목

1. OCR 재처리 뒤에는 기존 `ingest.run_chain`을 실행한다. PageIndex는 OKF 본문 fingerprint를 비교해 바뀐 문서만 다시 만들고, 이후 pgvector 단계도 같은 체인 순서로 실행한다.
2. 체인 완료 여부는 콘솔 문구만으로 판단하지 않고 `ingest.pipeline_run`의 `chain.run_chain` 상태와 `failed_steps` metrics를 함께 확인한다.
3. checksum 이전 형식의 PageIndex 트리는 첫 실행에서 재생성된다. 대량 재처리 때는 대상 수와 LLM 요약 처리 시간을 고려해 배치 크기를 조절한다.

이 보완은 의도 분석, 다중 데이터 소스 조회, OKF 근거 검증의 기존 구조를 바꾸지 않는다.
