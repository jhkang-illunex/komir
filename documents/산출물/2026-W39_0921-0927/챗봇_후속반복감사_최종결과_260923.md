## 4. 반영한 보완

### 수락 검사

- 공식 Tree/vector ID 변환과 원본 경로 대조, 공개 프로필의 비공개 원천 제외를 적용했다.
- fixture·현재 OKF·Tree 저장 hash를 대조하고, 실제 frontmatter 줄 수·node ID·문서 경로·원문 구간을 독립 계산한다. `read_node_text()`가 고정 문장만 꾸며 반환해도 통과하지 않는다.
- 실제 OKF를 다시 청킹한 텍스트 집합과 DB 청크 본문을 비교한다. count가 있다는 이유만으로 최신 색인이라고 판정하지 않는다.
- HWP는 ODT XML의 **니켈로 시작하는 같은 table-row**에서 두 사실을 확인한다. Excel은 원본의 B4·D3/D4·L3/L4와 OKF 표의 header → 열 위치 → 단위 행 값을 연결한다. 원본 소수 값의 OKF 6자리 반올림도 명시적으로 대조한다.
- `detail.required_checks`를 사전 정의 ID별 정확히 한 번 기록한다. 미실행은 SKIPPED와 이유를 남기며 전체 PASS를 금지한다. 확인된 FAIL이 환경 차단보다 우선한다.

### 문서 메타데이터

- HWP의 `니 켈`·`구 리`를 광종으로 인식한다. `아니 켈리`, `누구 리더`의 오탐을 차단하고 기존 `황산니켈`, `탄산리튬`, `니켈가격` 인식을 유지했다.
- 날짜는 유효한 달력 날짜인지 검사한다. 추출 레코드 → 제목 → 경로 → 명시 발행 표지 → 조달청 날짜 단독 머리글 순으로 근거를 좁혔다. 생산 개시일을 발행일로 만들거나 1999년을 2099년으로 바꾸지 않는다. 근거가 없으면 NULL이다.
- 유효한 OKF `document_date`를 실제 vectorizer SQL 입력의 `pub_date`로 전달한다. SQL 경계를 mock한 독립 검사에서 이 값을 None으로 되돌리면 실패함을 확인했다.

원본 → 저장 추출 텍스트 → OKF → Tree → vector 대조 결과와 후속 처리 명령은 [추출 메타데이터 감사](챗봇_추출메타데이터_감사_260923.md)에 있다. 같은 PageIndex 질의 `LME Seminar 니켈`에서 대상의 누락된 광종 메타만 임시 복사본에 보완하면 746위에서 1위가 되는 것을 [독립 재실행](acceptance_cycle3/astra_metadata_evidence_replay.log)으로 확인했다. 이 실험은 dense 개선을 입증하지 않는다.

## 5. 반복 기록과 잔여 범위

1. **Round 1:** 저장 원본과 기존 6건 FAIL의 원인을 조사했다. 공식 ID 규칙 누락, HWP 광종 누락, vector 날짜 전달 손실을 확정하고 두 세션의 파일 소유권을 분리했다.
2. **Round 2:** 첫 수정의 부정 입력에서 광종 일반 문장 오탐·날짜 세기 손실·제목보다 사건 날짜 우선 선택을 발견해 수정했다. 통합 검사에서는 HWP 다른 광종 행 혼입·Excel 열 교환·확정 FAIL과 DB 차단 우선순위를 보완했다.
3. **Round 3:** 33개 acceptance·46개 ingest 회귀, module 10건, 같은 조건의 integration 6건과 정상 대조군 부정 검사를 독립 실행했다. 이번 검사기·추출 코드 범위의 잔여 P1이 없어 종료했다. 실제 검색·저장물 실패는 위 표처럼 남겼다.

저장된 AC29 광종 메타, AC30·USGS Tree freshness, 확인된 날짜의 vector 반영은 **이번 실행에서 재처리하지 않았다**. 이는 이번 감사의 no-write 범위 때문이며 기존 사용자 재처리 요청에 새 승인이 반드시 필요하다는 의미가 아니다. 이어서 실행할 명령과 그룹 단위 vector 재적재의 영향은 추출 감사 문서에 정리했다.

고정 7개 원본·6개 통합 사례의 검사이며 전체 코퍼스의 추출 정확도나 모든 임베딩 벡터를 재계산해 확인한 결과는 아니다. `content_keywords`의 일반어·`col1` 같은 잡음은 관측했지만 이번 표본의 dense 실패 원인으로 확정하지 않았으므로 임의로 수정하지 않았다. live 32건의 독립 원천 수치 대조와 전체 실행은 별도 잔여 범위다.
