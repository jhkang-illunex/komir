- r9 기준 자료는 `/tmp/sol-action-full-r9-260921/*.json`의 `exit=0` 응답이다. `/tmp/sol-action-full-r9b-260921`은 서버 연결 실패(`curl` exit 7)이므로 판정에 쓰지 않는다.

## 판정 원칙과 회귀

- `slot_unresolved`는 위 필수 사례 모두 해결해야 한다. 재시도 후에도 슬롯이 불명확하면 실제 빠진 필드를 기록해 고치고, 단순히 실패 사유 문자열만 바꾸지 않는다.
- `source_unavailable`은 요청된 지표·광종·기간·조합을 **실제 데이터 원천과 조회 결과**로 확인해 부재가 입증된 경우 통과시킨다. 존재하는 자료를 라우팅 실패로 놓친 경우는 실패다. 출처 없는 수치, 다른 광종/지표의 대체 자료, 빈 표·차트는 허용하지 않는다.
- `out_of_scope`는 질문 원문이 실제 범위 밖일 때만 통과시킨다. Q30 원문은 “오늘 서울 날씨와 점심 메뉴를 추천해줘.”이므로 범위 밖이며, r9의 간결한 안내 응답은 통과다. 광물·KOMIS 질문을 잘못 범위 밖으로 분류하는 회귀는 허용하지 않는다.
- 수정 후 동일 세션·동일 질문으로 우선 사례와 관련 정상 사례를 재실행한다. 컨테이너 이미지 재빌드/재시작 후 이미지 태그·프로세스·캐시 상태를 확인하고 실제 `/pubchat` SSE의 답변·근거·표·차트·`done`을 보존한다. 공용 mapper/validator 변경은 기존 `inhouse/rag_core/tests` 회귀도 실행한다.
