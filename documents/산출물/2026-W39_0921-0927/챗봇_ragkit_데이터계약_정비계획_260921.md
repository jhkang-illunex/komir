# RAG Kit action 기반 질의 처리 재설계

작성일: 2026-09-21. **설계 문서**다. 이 문서로 서비스 코드·DB·컨테이너를 변경하지 않는다. 기준은 당일 30문항 실요청, `챗봇_30문항_ragkit_구조감사_260921.md`, `documents/meta/WORKLOG.md`의 신규 DB 연계 결정이다. 이전의 질문 문자열별 분기 추가 계획을 이 설계로 대체한다.

기존 기능 요구의 1차 정본은 `documents/기획문서/order/chatbot_rule.txt`다. `documents/기획문서/order/rag_chatbot/대화형검색시스템_피드백.md`와 `documents/산출물/2026-W38_0914-0920/챗봇_요구사항_준수현황_종합판정_260918.md`를 보조 근거로 사용한다. 아래 설계는 기존의 메뉴 안내·문서 검색·원자료 안내·예외 처리·응답 형식도 포함한다.

## 목표와 기준

같은 작업은 광종·기간·지역·가격 기준이 바뀌어도 같은 action을 실행한다. 예를 들어 `광종 X의 지난 1년 가격 조회`는 언제나 `price.series(mineral=X, period=trailing_1y)`다. X가 니켈·구리·텅스텐으로 바뀌거나 `지난 12개월 가격`, `최근 1년 시세`로 표현돼도 action 구현을 바꾸지 않는다. 질문 문구나 Q번호, `300%` 같은 임계값을 코드 분기 키로 쓰지 않는다.

실행 순서는 **① intent 파악 → ② action 선택·조합 → ③ slot filling → ④ 도구의 `extract_data` → ⑤ advisor 검증 → ⑥ 결과 생성**이다. 각 단계는 타입이 있는 결과를 다음 단계에 전달한다. `mineral_risk` 과거 산출물과 `expired/`는 결과 원천으로 사용하지 않는다. 새 DB에서 받을 수급위기 진단·수요예측·가격/수요량 예측·지정학위기 지수와 연계 기사는 DB 제품·스키마·접속·필드가 미정이므로 모두 `unavailable`이다.

## 단계별 계약

| 단계 | 책임과 출력 | 실패 시 동작 |
|---|---|---|
| ① Intent LLM | 원문·확정된 대화조건에서 목표를 `retrieve_value`, `compare`, `verify_claim`, `explain_document`, `explain_concept`, `scenario`, `menu`, `off_topic` 등으로 추출한다. 복합 질문은 독립 목표를 여러 개 낸다. | 구조화 출력 오류·불명확한 지시어는 `intent_unresolved`; 검색 0건 |
| ② Action planner | Intent를 아래 action 카탈로그의 ID 목록과 의존 DAG로 바꾼다. **카탈로그와 capability matrix만** 사용한다. | action이 없거나 지원하지 않는 조합은 `unsupported_action`/`unsupported_combination`; 검색 0건 |
| ③ Slot filling LLM | 각 action의 Pydantic 인자 모델을 채운다. 광종·HS·지역·기간·관측/예측 구분·가격 기준·집계·출력 형식·비교 임계값을 원문과 확인된 대화 상태에서만 채운다. | 필수 슬롯 누락·모순·도구가 지원하지 않는 값은 `slot_unresolved`; 검색 0건. 정규식으로 우회하지 않는다. |
| ④ `extract_data` | 허용된 도구 어댑터에 검증된 슬롯을 전달하고 `Evidence(requirement_id, action_id, source_id, observed_period, unit, payload, citation, caveats)`를 반환한다. | 도구 실패·원천 부재·요청 기간 자료 부족을 유형별로 반환한다. 다른 문서를 대체 원천으로 자동 검색하지 않는다. |
| ⑤ Advisor | 요구별 Evidence의 지표 의미·광종·기간·단위·모집단·신선도·인용 직접성을 검사한다. `Advice(approved, supported_evidence_ids, missing_requirements, reason)`를 생성한다. 결정적 필수 필드 검증과 LLM 의미 검증을 모두 적용한다. | 한 요구라도 근거가 부족한데 부분 답변 capability가 검증되지 않았으면 전체 기권한다. `approved=false`일 때 생성 호출 0건. |
| ⑥ Generator | 승인된 Evidence ID와 caveat만 사용해 본문·표·차트·출처를 생성한다. 없는 수치·원인·연결 기사를 만들지 않는다. | 최종 인용 번호/표·차트 원천 정합성 실패 시 본문 공개 전 기권한다. Advisor를 생성 후로 미루지 않는다. |

①과 ③은 한 번의 구조화 LLM 호출로 묶을 수 있지만 결과 모델에는 **intent, action ID, 슬롯, 출처가 없는 추론의 표시**가 구분되어야 한다. ②와 원천 사용 가능성 판정은 결정적 코드다. ④ 이전에 `ActionPlan` 전체를 검증한다. 질문 원문을 ④의 검색어로 통째 전달하는 경로, LLM 오류 시 regex·동적 호환 폴백으로 임의 action을 여는 경로, ⑤ 없이 정형 근거를 무조건 통과시키는 경로는 제거 대상이다.

### 타입과 슬롯

`ActionPlan`은 비어 있지 않은 `ActionCall` 목록, `turn_id`, `history_refs`, `complete`를 갖는다. `ActionCall`은 안정적인 `requirement_id`, 카탈로그의 `action_id`, `slots`, `depends_on`, `requested_outputs`를 갖는다. Pydantic `extra=forbid`로 미정 필드를 거부한다. 광종은 별칭을 공식 광종 ID로 해소하되 해소 실패를 다른 광종으로 바꾸지 않는다. `Period`는 `trailing_months`, `calendar_year`, `start/end`, `latest`, `future_horizon` 중 하나로 정규화하고 현재 날짜와 실제 관측일을 구분한다. `MetricBasis`는 금액/중량, 가격 기준·통화·중량단위, flow/snapshot 여부를 분리한다. `Claim`은 비교값(예: 150, 300, 400)과 연산자·단위를 슬롯으로 보유한다. 단위를 모르면 `null`로 남기며 생성 단계가 추정하지 않는다.

후속 질문은 직전 **승인된** `ActionCall`의 광종·기간·가격 기준만 명시된 지시어에 맞춰 승계한다. 예를 들어 Q23→Q24는 Q23의 실제 조회기간을 공통 비교기간으로 사용하고, Q25는 Q24의 비교 집합을 승계한다. 사용자 원문에 없는 기간·지역을 모델이 임의로 보충하지 않는다.

기간 슬롯에는 `explicit` 여부도 기록한다. 명시 기간이 있으면 요청 범위를 조회하고 실제 자료의 시작·끝과 결측을 알린다. 기간이 없으면 설정된 최대 반환 길이를 적용한다. 예전 문서의 “시계열 기본 1개월·3개월 확대”와 최근의 “명시 기간 우선, 미명시 시 환경변수 최대 길이” 결정이 충돌하는 부분은 최근 결정을 실행 규칙으로 삼고, 기본 표출 간격과 조회 길이는 별도 슬롯으로 둔다. 전체 원자료 요청은 응답 행 수 제한을 우회하지 않고 해당 데이터 메뉴로 안내한다.

## 기존 챗봇 요구사항 추적표

| 정본 요구 | action·slot·출력 계약 | 검증 기준 |
|---|---|---|
| 유형 1: 표·차트 명시 | `requested_outputs`에 `table`/`chart`를 보존하고 승인된 Evidence로 렌더링 | 요청 형식과 실제 SSE 이벤트 일치; 표·차트의 수치·단위·기간이 본문과 일치 |
| 유형 2: 단일 수치·사실 | `price.series`, `indicator.series`, `trade.*` 등에서 `latest`/극값 집계; 요약·기준일·상세표·메뉴 | 근거 수치와 기준일을 표시하고 다른 시점 자료를 오늘 값으로 쓰지 않음 |
| 유형 3: 추이·변화 | 기간·집계 간격을 별도 slot으로 보존; 시계열 요약·차트·상세표 | 명시 기간 우선, 미명시 시 설정 길이; 결측·실제 관측범위 표시 |
| 유형 4: 비교 | 같은 기준의 복수 `ActionCall`과 결정적 비교 연산; 비교표 | 광종·단위·시점 정렬, 계산식·모집단 제시 |
| 유형 5: 원인 해석 | 정형 action과 `document.retrieve`의 복합계획; 원인 주장은 별도 Evidence 요구 | 현재 미검증 조합은 기권; 관련 문서의 동시 발생을 인과로 단정하지 않음 |
| 유형 6: 원자료 전체 | `dataset.navigate`가 검증된 메뉴 레지스트리의 경로·링크 반환 | 전체 데이터 화면 안내; 제한된 응답 표를 전체 원자료로 부르지 않음 |
| 유형 7: 메뉴 안내 | 기존 `page_recommend`를 `menu.navigate` 어댑터로 연결; 후보·경로·링크 | 존재하지 않는 메뉴 추측 금지; 복수 후보와 이동 안내 유지 |
| 유형 8: 범위 밖·모호·데이터 없음 | `off_topic`, slot/capability/adapter 오류를 사유 코드로 구분 | 투자·개인정보·무관 주제·미지원 광종·기간 공백·모호 질문별 안내; 무관 검색 0건 |
| 유형 9: 기타 근거 질문 | `document.retrieve` 뒤 직접 근거 검증; 근거 메뉴 표시 | 출처 없는 내부 LLM 지식만으로 개념·사실 답변 금지 |
| 공통: 어투·출처 | Generator 격식체; 수치·문서 답변의 Evidence ID와 출처 메타데이터를 `done` 및 근거 패널에 전달 | 본문 인용, 근거 데이터 행, 출처 리스트의 ID와 개수 일치; 메뉴·기권에는 허위 출처 없음 |
| 공통: 멀티턴 | 세션의 승인된 plan·slot·관측범위·근거 ID를 상태로 저장 | 지시어·대용어를 이어받고 잘못된 이전 답변은 승계하지 않음 |
| 공통: 진행·실패 상태 | 기존 SSE 계약으로 질문 조건 확인→답변 준비→데이터 분석→답변 생성 상태를 송신; 실패 사유도 송신 | 실패 시 마지막 상태와 사유가 모순되지 않음; 실행하지 않은 단계를 진행 완료로 표시하지 않음 |
| 도입부 고정 질문 4개 | Q01·Q03·Q02·Q04와 각각 같은 action plan으로 진입 | 클릭 시 즉시 전송; Q02의 광종별 지표 범위 불일치를 임의 값으로 메우지 않음 |

형식·상태·출처는 별도 질문별 후처리가 아니라 모든 action에 공통인 `ResponseContract`로 둔다. `ResponseContract`는 `requested_outputs`, `summary`, `data_rows`, `charts`, `citations`, `menu_links`, `status`, `failure_reason`을 포함한다. 수치·문서 Evidence가 없으면 해당 데이터 행·차트·출처를 비운다. `menu.navigate`에는 검증된 메뉴 링크가 필요하지만 데이터 출처 인용을 요구하지 않는다. 기존 public/private 접근권한과 메뉴 레지스트리 경계는 어댑터에서 유지한다.

### 「대화형검색시스템_피드백」 추가 반영

| 피드백 요구 | 설계 반영 | 확인 방법 |
|---|---|---|
| 메뉴의 계층 경로·클릭 링크·복수 후보·이동 안내 | `menu.navigate` 결과를 경로 단계와 링크의 목록으로 정의한다. 확인 불가 메뉴는 실패 사유를 반환한다. | 단일·복수 후보, 미등록 메뉴를 각각 실제 레지스트리와 대조 |
| 수치의 출처·기준일시·단위와 근거 패널 | Evidence에 관측일, 산출/수집 기준일, 단위를 분리하고 `ResponseContract`로 전달한다. | 본문·표·차트·근거 패널·출처 목록이 같은 Evidence ID를 참조 |
| 문서 목록·요약·발행일·원문 링크 | `document.retrieve`의 Evidence에 문서 제목, 발행일, 직접 근거 절, 허용된 원문 링크를 요구한다. 링크가 없으면 링크를 만들지 않는다. | 검색 결과마다 문서 식별자와 직접 근거를 대조; 누락 필드 표시 확인 |
| 지표 변화와 관련 문서의 병렬 제시 | 서로 다른 requirement와 Evidence로 보존한다. 지표의 원인이라고 주장하려면 별도의 원인 근거가 필요하다. | 관련 기사만 있는 경우 인과 단정 없음; 현재 미검증 복합 경로는 기권 |
| 예외 사유별 안내 | `unsupported_mineral`, `no_data_for_period`, `insufficient_data`, `slot_unresolved`, `access_denied`, `out_of_scope`, `investment_advice` 등을 안정적 실패 코드로 정의한다. | 각 실패 코드에 맞는 안내; 가용 광종·기간·메뉴는 실제 레지스트리/도구 결과로만 제시 |
| 진행 상태와 조회 실패 상태 | action plan 검증·도구 조회·Advisor·생성의 실제 전이에 기존 SSE 상태값을 매핑한다. | 도구 오류와 자료 없음에 `조회실패` 및 정확한 사유 송신 |

피드백 문서의 예시 DB·GDELT·뉴스 원천과 미래 제공 시점은 현재 연결 사실로 간주하지 않는다. 레지스트리의 실제 원천과 접근권한을 확인한 action만 실행한다. 피드백 문서의 “3개월 이상이면 기간 재지정” 예시는 최근 사용자 결정인 명시 기간 조회 우선 규칙으로 갱신한다. 조회 가능 범위 밖의 기간은 실제 가용 범위를 안내한다.

| `trade.concentration` | mineral, period, measure | 전체 국가 비중과 HHI; 표본 상위 N개만으로 재계산 금지 | available |
| `trade.hs_summary` | hs_code, period | 명시 HS의 품목명·전체 국가 합계; 광종 전체와 구분 | available |
| `resource.rank` | mineral, metric=production/reserves, year, top_n | 생산량(flow)과 매장량(snapshot)의 서로 다른 연도 집계 규칙 | available |
| `indicator.series` | indicator_id, period, mineral_scope | 공식 KOMIS 지표 정의와 공개 프로필 확인 | 조건부 available |
| `document.retrieve` | topic, source_scope, period | 문서·개념 출처 검색, 직접 뒷받침하는 절만 반환 | available, source-first |
| `menu.navigate` | target_page, audience | 기존 `page_recommend`의 검증된 계층 경로·링크·복수 후보 | available |
| `dataset.navigate` | dataset, mineral, period | 전체 원자료를 제공하는 검증된 메뉴 경로·링크 | 메뉴 항목 확인 시 available |
| `diagnosis.rank/series` | mineral(s), week, score/grade/cause | 향후 새 DB; 현재 어댑터 없음 | unavailable |
| `forecast.demand/price/quantity` | mineral, target, horizon, unit | 향후 새 DB; 현재 어댑터 없음 | unavailable |
| `geopolitics.index/articles` | mineral, as_of, linked_event | 향후 새 DB의 지수·기사 연결키; 현재 어댑터 없음 | unavailable |
| `stockpile.status` | mineral, target, days | 검증된 공식 원천/계약 없음 | unavailable |
| `scenario.assess` | premise, horizon, affected_actions | 사실과 가정을 분리해 증거가 있는 범위만 평가 | 근거·capability 확인 전 unsupported |

`source_document`와 `concept`는 `document.retrieve` 뒤 Advisor가 직접 근거를 인정한 경우에만 설명한다. 광종명이 같다는 이유만으로 연례보고서의 다른 절을 정책·진단·지정학 기사 근거로 쓰지 않는다. `indicator.series`의 수급동향·시장전망과 `diagnosis.*`의 위기 점수는 다른 action이다. 가격 관측과 가격 예측도 다른 action이다.

## 원천 레지스트리와 capability

레지스트리 항목은 `action_id`, `source_id`, `availability`, `profile`, `allowed_tools`, `required_fields`, `freshness_rule`, `citation_rule`, `adapter_version`을 갖는다. 새 DB 대상의 `source_id`는 논리 ID만 기록하고 실제 DB명·테이블·접속 값을 만들지 않는다. 새 DB가 확정되면 원천 소유자, PK·광종 키, 관측일/기준주, 점수·등급·원인, 예측 대상·수평선·단위, 지수·기사 연결키, 수정시각과 결측 의미를 실측해 어댑터를 연다. 계약 미충족이면 `unavailable`을 유지한다.

Capability matrix는 action 단독·조합, 요구별 Evidence 매핑과 부분 답변 허용 여부를 관리한다. 현재 `price.series + document.retrieve`, `resource.rank + document.retrieve`, 미연결 action이 섞인 요청은 **전체 기권·도구 호출 0건**이다. `price.compare`, 생산량+매장량, 생산국 비중+수입국 비중처럼 이미 검증된 구조화 조합만 허용한다. 향후 요구별 검색어·근거 ID·Advisor 승인·출처 표시까지 테스트한 조합만 열 수 있다. 정보가 없는 광종·기간은 `no_data_for_period`나 `unsupported_mineral`처럼 실제 사유를 반환한다.

## 현재 rag-kit에서 옮기는 순서

1. 기존 SQL·MCP 집계는 어댑터 뒤에 보존한다. 먼저 action별 입력·출력 Pydantic 모델과 원천 레지스트리를 만들고, 현재 함수가 어떤 action을 구현하는지 매핑한다. 가격 비교의 계산식·통관 전체 모집단 집계는 재작성하지 않는다.
2. 기존 `KomirJsonLLM` 구조화 출력으로 `ActionPlan`을 만들고, 고정된 카탈로그와 슬롯 검증을 통과한 계획만 실행한다. 원문을 직접 재분류하는 `_safe_route_fallback`, `_apply_aggregate_route`의 문구별 분기, Q번호·숫자·광종 목록 조건은 action 경로로 옮긴 뒤 제거한다. 오류 시 과거 라우터로 조용히 돌아가지 않는다.
3. `extract_data`가 모든 어댑터 근거에 requirement/action ID를 붙인다. Advisor를 생성 **이전**에 단일 경계로 두고 필수 필드와 의미 적합성을 검사한다. 기존 verify·near-miss·인용 검사는 이 계약에 편입하되 unsupported 결과를 근접 문서로 제안하지 않는다.
4. 테스트 컨테이너에서 새 경로를 먼저 검증한다. 전환 전·후 같은 질문과 데이터 스냅샷으로 SSE·표·차트·인용·지연 시간을 비교한다. 캐시·이미지 해시를 확인한다. 운영 배포는 이 설계의 범위가 아니다.

## Sol 검증과 합격 기준

- **단계 경계:** intent/slot 실패, 미연결 원천, 미지원 조합에서 `extract_data=0`, `advisor=0`, `generate=0`. 도구 성공 후에는 Advisor가 생성보다 먼저 호출되고, `approved=false`일 때 `generate=0`이다. 정형 근거의 무조건 fast-pass, 생성 후 Advisor, regex fallback이 없어야 한다.
- **카탈로그 속성 테스트:** `니켈/구리/텅스텐의 지난 1년 가격`, `최근 12개월 시세`, 문장 순서 변형이 모두 `price.series`에 매핑되고 광종·기간 슬롯만 달라야 한다. 150/300/400% 전제는 모두 `price.verify_claim`에 매핑한다. Q05·Q06의 `년`, `비교하고`가 광종 슬롯에 들어가면 실패다.
- **원천 경계:** Q08·Q09·Q16 및 진단·수요/가격/수요량 예측·지수·연계 기사 변형은 도구 호출·대체 인용 0이다. 수급동향지표와 관측 가격은 과차단하지 않는다. 단독 `가격 분석 보고서 요약`은 `document.retrieve`이며 가격값 요구와 혼동하지 않는다.
- **조합·대화:** `가격+문서`, `생산량+정책 문서`, 미연결 결과 포함 요청은 어순·접속사·마침표·줄바꿈이 바뀌어도 현재는 동일하게 기권한다. Q23→Q24→Q25는 실제 기간·광종 집합을 승계한다. 두 구조화 요구가 허용된 Q04·Q11·Q13·Q29는 각각의 근거가 남아야 한다.
- **전수·실요청:** Q01~Q30과 원문 밖 변형을 실제 `/pubchat`에 보내 원시 SSE/출처/표/차트를 보관한다. 과거 13 통과·7 부분·10 실패는 당시 기록이며 현재 점수가 아니다. 가격·원자료 기간 부족, `DEV_DUMMY`, private 프로필 제한은 코드 결함과 나눠 판정한다. 지연은 intent/slot p50·p95, 전체 첫 토큰·완료 p50·p95, 도구 호출 수를 같은 조건에서 측정한다.

완료 조건은 **동일 action의 슬롯 변형 일관성, 미연결 원천 대체 인용 0, Advisor 승인 전 생성 0, 기존 가격·교역·생산 집계 회귀 없음, 30문항과 변형의 재현 가능한 판정**이다.
