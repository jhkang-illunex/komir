# 챗봇 피드백 잔여 항목 검증 결과

작성일: 2026-09-24

이번 확인은 주간 리밋 절약을 위해 피드백 잔여 항목 중 다음 세 범위만 다뤘다.

1. 피드백 대응 상태표 갱신
2. 리튬 수입수요예측 메뉴 안내 대표 검증
3. `evidence_status`·`no_evidence` 현재 코드 계약 확인

## 1. 피드백 대응 상태

| 항목 | 판정 | 근거 |
|---|---|---|
| 페이지 안내 공통 형식 | PASS | typed action과 일반 추천 모두 공통 renderer 사용, 관련 단위검사 통과 |
| 가격·무역지표·출처·표·차트 | PASS | 배포 회귀 및 라이브 수락검사 통과 |
| OCR PDF/HWP/Excel 대표 문서 연결 | PASS | AC28·AC29·AC30·AC41 통합검사 통과 |
| pgvector 문서·임베딩 연결 | PASS | AC28·AC29·AC30·AC39·AC41 통합검사 통과 |
| 리튬 수입수요예측 메뉴 | 보완 후 PASS | 정식 page_id/URL이 없어 추측 추천을 차단하도록 배선하고 단위검사 추가 |
| RCA·TII 세계 분모 provider | 보류 | 원천 연결 전 `source_unavailable` fail-closed 정책 유지 |
| 가격예측 비교랭킹 | 잔여 | 기존 피드백 문서상 미구현이며 이번 범위에서 착수하지 않음 |
| `evidence_status`·`no_evidence` 외부 계약 | 협의 대기 | 내부 상태·경고는 존재하지만 프론트 표시값/규칙은 합의 전 |

## 2. 리튬 수입수요예측 메뉴 검증

기존 배포 서버 대표 질의에서 등록되지 않은 인접 페이지를 3개 추천하는 동작을
확인했다. 원인은 `is_unverified_import_demand_forecast_menu()`가 구현되어
있었으나 라우터에서 호출되지 않은 배선 누락이었다.

보완 후에는 메뉴·페이지·경로를 묻는 수입수요예측 질의를
`not_found` 정책으로 종료하고, 확인되지 않은 URL을 추측하지 않는다. 단순히
수요예측 수치를 묻는 문장은 메뉴 미확인 정책에 잘못 걸리지 않도록 구분한다.

## 3. `evidence_status`·`no_evidence` 현재 계약

- `SourceAssessment`는 원천 미연결 도메인, 차단 여부, 지원하지 않는 조합,
  추출 유효성을 내부적으로 보유한다.
- 미연결 수요예측·진단·가격예측 등은 결정적으로 차단하고,
  `source_unavailable` 계열 안내를 사용한다.
- PageIndex 에이전트에는 `pageindex_agent_no_evidence` 경고가 존재한다.
- 현재 프론트에 노출할 표준 `evidence_status` 값과 `no_evidence` 표시 문구는
  외부 계약으로 확정되지 않았다. 따라서 이번 작업에서는 임의의 공개 필드나
  UI 표시 규칙을 추가하지 않았다.

## 결론

이번 범위에서 실제 코드 보완이 필요한 항목은 수입수요예측 메뉴의 미확인 경로
배선 1건이었고, 단위검사를 통과했다. 나머지는 기존 PASS를 재확인하거나 정책·
데이터 원천 협의가 필요한 잔여 항목으로 기록했다.

수정 커밋 `a3aeda1ae`를 `komir-rag-chat:a3aeda1ae`로 배포한 뒤 대표 질의를
재실행했다. 응답은 `status=not_found`, `recommendations=[]`,
`warnings=["unverified_menu_path"]`로 확인됐고, 기존 15·65·6·33·1건 게이트와
라이브 회귀검사도 통과했다.
