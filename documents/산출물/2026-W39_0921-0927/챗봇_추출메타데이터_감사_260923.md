## 결론

> 아래 결론은 위 follow-up 적용 전 읽기 전용 감사에서 확정한 역사적 상태다.

확정된 메타데이터 결함은 두 건이다.

1. AC29 HWP의 OCR형 `니 켈`·`구 리`가 연속 문자열 검사에서 빠져 OKF와 PageIndex의 `minerals=[]`가 됐다. 현재 실제 PageIndex `LME Seminar 니켈` 조회에서 대상은 1,546개 후보 중 746위(0.333)다. 격리 트리에서 이 문서에만 `['구리', '니켈']`를 반영하면 1위(0.667)가 됐다. 이는 PageIndex 문서 선택에 대한 영향이며 dense top-10 부재를 이 메타데이터 하나의 원인으로 단정하지 않는다.
2. OKF vectorizer가 유효한 `document_date`를 `DocRecord.doc_date=''`와 SQL `pub_date=None`으로 버렸다. 실제 AC41 세 문서와 USGS의 현재 pgvector `pub_date`는 모두 NULL이다. dense 검색은 날짜 질의에서 `pub_date`만 순위 보너스로 사용하므로, AC41의 확인된 날짜가 dense 날짜 검색에 전달되지 않는다.

현재 dense 수락 실패는 같은 원인으로 묶을 수 없다. AC28·AC30은 고정 질의의 top-10에 대상 문서가 없다. AC39는 기대 USGS 문서가 1위이지만 고정 사실 문구는 top-10 어느 청크에도 없다. AC41은 실제 청크가 있으나 full Tree ID와 16자 vector ID 비교가 실패를 만든다. vectorizer의 기존 16자 ID 계약은 담당 범위 밖이며 수정하지 않았다.

## 검색 경로 판정

- `inhouse/ingest/vectorize/build_pgvector_okf.py`는 YAML을 읽은 뒤 본문만 `DocRecord.raw_text`로 넘긴다. 프론트매터의 광종·키워드는 dense 임베딩 텍스트에 들어가지 않는다.
- `inhouse/rag_core/retrieval/dense_pg.py`는 `embedding`, `src`, 그리고 날짜 질의일 때 `pub_date`만 SQL에 사용한다. 광종·키워드 필터는 없다.
- `inhouse/rag_core/retrieval/pageindex.py`의 `find_documents()`는 Tree의 `minerals`와 `content_keywords`를 문서 후보 점수에 포함한다. AC29의 광종 손실은 이 단계에 실제 영향이 있다.
- AC40은 doc filter로 USGS Tree를 정확히 고른 뒤, 노드 제목·요약 점수가 line 207의 `SIGNIFICANT EVENTS, TRENDS, AND ISSUES`를 line 49 `FOREWORD`보다 앞세운 문제다. Tree 메타데이터가 아니라 PageIndex 노드 검색/요약 문제로 분리한다.

## 반영한 최소 수정

수정 파일 소유권은 다음 네 개로 한정했다.

- `inhouse/ingest/okf/build_okf_documents.py`
- `inhouse/ingest/vectorize/build_pgvector_okf.py`
- `inhouse/ingest/tests/test_build_okf_documents.py`
- `inhouse/ingest/tests/test_build_pgvector_okf.py`

`build_okf_documents.py`는 기존 연속 광종 별칭 매칭을 유지하고, 새로 허용하는 한글 음절 간 공백에만 단어 경계와 허용 조사를 적용했다. 따라서 `니 켈의`는 인식하지만 `아니 켈리`, `누구 리더`는 인식하지 않는다. `황산니켈`, `탄산리튬`, `니켈가격`의 기존 연속 매칭도 회귀 검사했다.

날짜는 달력 유효성을 검사하고, 추출 레코드 날짜 → 제목 → resource → 본문의 `발행일`·`발간일`·`작성일`·`Published` 등 명시 표지와 같은 줄 → 조달청 OCR 첫 8개 비공백 줄의 날짜만 있는 헤더 순으로 선택한다. 일반 본문의 생산·사건 날짜는 문서 발행일로 만들지 않는다. 이 근거가 없는 문서는 unknown/NULL을 유지한다. AC41의 실제 헤더 날짜는 유지한다. 연·월만 있는 AC28·USGS는 NULL을 유지한다.

`build_pgvector_okf.py`는 유효한 ISO `document_date`를 손실 없이 `DocRecord`에 전달하고 SQL row의 `pub_date`에 `datetime.date`로 넣는다. 1999-12-31도 2099로 바꾸지 않는다. Tree와 pgvector의 ID 길이 계약은 변경하지 않았다.

현재 OKF·Tree·DB는 이 수락검사 감사의 no-write·DB 재색인 제외 범위 때문에 재생성하거나 갱신하지 않았다. 따라서 AC29 저장 메타와 현재 `pub_date=NULL`은 아직 그대로이며, 코드 수정만으로 수락 결과가 PASS가 되지 않는다. 이는 기존 사용자 요청의 재처리 권한을 부정하거나 새 사용자 승인이 반드시 필요하다는 뜻이 아니다.

## 후속 실행 범위와 영향 (미실행)

다음 명령은 현재 CLI와 함수 시그니처를 확인해 작성했으며, 이 감사에서는 실행하지 않았다.

| 대상 | 검토 가능한 범위 명령 | 쓰기 영향과 목적 |
|---|---|---|
| AC29 OKF 메타 | `cd inhouse && python -m ingest.okf.build_okf_documents --enrich-metadata --metadata-pattern '1019_LME_Seminar에서_발표한_품목별_동향_및_전망.md'` | 일치하는 기존 OKF 한 파일의 frontmatter만 갱신한다. 원본 재추출은 하지 않는다. |
| AC29 Tree 메타 | `cd inhouse && python -c "from pathlib import Path; from ingest.pageindex.build_pageindex_trees import sync_tree_metadata_for_okf; from ingest.paths import get_paths; p=get_paths(); print(sync_tree_metadata_for_okf(p.okf_documents/'조달청보고서/1019_LME_Seminar에서_발표한_품목별_동향_및_전망.md', p.pageindex_trees/'조달청보고서/1019_LME_Seminar에서_발표한_품목별_동향_및_전망.tree.json'))"` | public `--sync-metadata` CLI는 전체 tree를 순회하므로 쓰기 범위를 넓힐 수 있다. 이 함수 호출은 AC29 Tree 한 파일만 동기화한다. |
| AC30 stale-hash Tree | `cd inhouse && python -m ingest.pageindex.build_pageindex_trees --pattern 'Ni_Weda_Bay_2025_Prod_AR_260814__2.md' --force` | pattern에 일치하는 AC30 Tree만 재생성한다. 요약 생성은 현재 LLM 가용성에 따른다. |
| USGS stale-hash Tree | `cd inhouse && python -m ingest.pageindex.build_pageindex_trees --pattern 'USGS_2026.md' --force` | pattern에 일치하는 USGS Tree만 재생성한다. AC40 노드 문장 회수 문제의 해결을 보장하는 명령은 아니며, body hash freshness만 복구한다. |
