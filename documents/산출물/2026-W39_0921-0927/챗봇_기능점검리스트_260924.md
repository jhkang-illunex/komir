## 2. 판정 규칙

- `PASS`: 기대 계약과 실제 결과가 일치하고 재현 명령 또는 증거 파일이 있다.
- `FAIL`: 서버 오류, 잘못된 action, 잘못된 출처·수치·단위, 내부 식별자 노출이 하나라도 있으면 실패다.
- `BLOCKED_DATA`: 성공을 판정할 원천 표본이 없을 때만 사용한다. 정상 기권 계약을 `PASS`로 바꾸지 않는다.
- `미검증`: 아직 해당 조건을 실행하지 않은 상태다. 과거 다른 케이스의 성공으로 대체하지 않는다.

### 2.1 답변 결과 분류

기권 여부만으로 합격시키지 않고 terminal payload의 `reason_code`, `message_key`,
`needs_clarification`, `abstained`, `actions`, `citations`, 표·차트 존재 여부를 함께 기록한다.

| 결과 분류 | 의미 | 대표 케이스 | 판정 |
|---|---|---|---|
| `ANSWER_PASS` | 답변이 요구된 질문에 근거·수치·단위·표·차트 계약까지 충족 | AC01~AC18 성공 요구 케이스, AC22 후속 턴 | PASS |
| `ABSTAIN_DATA_UNAVAILABLE` | 질문은 충분하지만 검증된 원천·관측값·세계 분모가 없음 | AC19 RCA, AC20 TII, AC32 미래 실측, AC33 미연결 진단, Q02/Q26/Q27 | 기대된 정확한 `source_unavailable`이면 PASS, 그 외 FAIL |
| `CLARIFICATION_REQUIRED` | 질문 슬롯(광종·연도·국가·지표 등)이 부족하거나 모호함 | AC21 첫 턴 | `needs_clarification=true`; 숫자·표·차트 생성 시 FAIL |
| `UNSUPPORTED_SCOPE` | 질문이 서비스 범위 밖이거나 지원하지 않는 광종·조합임 | AC31, AC34, AC35, AC36 | 기대된 `out_of_scope`/`unsupported_combination`이면 PASS |
| `ANSWER_FAILURE` | 답변이 요구됐는데 서버 오류, timeout, 빈 답변, 잘못된 action, 근거 불일치가 발생 | 성공 기대 케이스의 5xx·빈 응답·검색 불일치 | 항상 FAIL; 데이터 없음으로 소급 금지 |
| `BLOCKED_ENV` | DB·임베딩·PageIndex 등 실행 환경 자체를 사용할 수 없음 | 통합 검사 연결 불가 | 원인·명령·환경을 기록하고 PASS로 집계하지 않음 |

`ABSTAIN_DATA_UNAVAILABLE`와 `CLARIFICATION_REQUIRED`는 서로 대체하지 않는다. 질문이
불충분하면 먼저 명확화를 요구하고, 질문이 충분하지만 원천이 없을 때만 데이터 부재
기권으로 판정한다. 성공 답변을 요구한 케이스의 검색 실패는 데이터 부재가 명시적으로
계약된 경우를 제외하고 `ANSWER_FAILURE`다.

### 6.2 수정 적용 상태

다음 보완을 로컬 코드에 적용했다. 배포 컨테이너에는 아직 반영하지 않았으므로
라이브 PASS로 승격하지 않는다.

| 대상 | 보완 내용 | 결정적 검증 |
|---|---|---|
| AC07 | `price.verify_claim`의 질문에 명시된 백분율·비교어를 typed 슬롯으로 보완 | 가격 주장 계약 테스트 PASS |
| AC18 | 특정국 의존도·TSI/RCA/TII/증감률 표현을 `trade.indicator` typed metric으로 정규화 | 의존도 action 계약 테스트 PASS |
| AC22 | 명확화 후속 턴을 재분류하지 않고 기존 typed 계획에 명시 슬롯만 병합 | 후속 슬롯 병합 테스트 PASS |
| AC36 | 수급동향·시장전망·광물종합 지표 표시명을 typed indicator로 정규화 | private indicator action 계약 테스트 PASS |
| AC38/AC46 테스트 계약 | 내부 파일명 기대를 공개 출처 라벨 기대으로 갱신 | module 10/10 PASS |

수정 후 결정적 회귀는 action contract 33건, 페이지·메뉴·공식 출처 15건,
module 수락검사 10건이 PASS했다. AC07·AC18·AC22·AC36의 배포 이미지 재검증은
새 이미지를 배포한 뒤 동일 case ID로 수행해야 한다.

- `komis_report_generator`와 registry의 **전체 페이지별** URL·필터·화면 구성 대조(P02~P05).
- S02~S05를 실제 질의해 답변·표·차트·citation의 공식 URL을 확인(L04).
- AC01~AC48 전체 live 재실행과 AC21→AC22 멀티턴 원본 보존(F04·F05).
- 반복 요청·장시간 SSE 안정성 및 5xx/traceback 확인(L05).
- AC07·AC18·AC22·AC36의 수정 사항을 새 이미지에 반영한 뒤 표적 라이브 재검증.
- AC17의 실제 원천 사전조건 증거 확보 후 `ABSTAIN_DATA_UNAVAILABLE` 여부 재판정.

위 미완료 항목은 현재 배포 smoke PASS를 전체 기능 PASS로 확대 해석하지 않는다.
