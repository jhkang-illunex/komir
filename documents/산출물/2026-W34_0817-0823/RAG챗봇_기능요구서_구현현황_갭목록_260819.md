## 2. 현재 구현 현황(코드 직접 확인, `rag` 브랜치)

### 2-1. 아키텍처 개요
`services/rag_chat/app/routers/chat.py`(SSE API 진입점) → `intent.py`(LLM 1회로 **document**
vs **page** 2경로 자동분류, mode=auto 기본) → 두 갈래:
- **document 경로**: `rag/ragkit/chatbot.chat_turn()` → `chatbot_graph.retrieve_evidence()`
  (route→retrieve→verify→reformulate LangGraph) → `generate.py` 인용강제 생성 →
  `chatbot_events.py` 표/차트 이벤트 → `chatbot_store.py` 세션 영속화(DuckDB
  `chat_session`/`chat_message`).
- **page 경로**: `page_recommend/`(43개 KOMIS 페이지 레지스트리, `komis-report-generator-main`
  이식) — 시나리오 2-5(메뉴안내)를 사실상 이 서브시스템이 담당.

### 2-2. 시나리오별 구현 대응
| 시나리오 | 구현 여부 | 근거 |
|---|---|---|
| 2-1 통계조회 | **구현됨(2026-08-19 end-to-end 검증 완료)** | `structured.py` 3템플릿(`latest_diagnosis`/`import_forecast`/`geo_index_trend`), 화이트리스트 방식(자유형 NL→SQL 금지). **최초 작성 시점엔 "코드 존재"만 확인하고 실제 데이터소스 연결은 미검증이었음 — 실측해보니 이 워크트리 `.env`에 `MSR_DB`가 아예 미설정이라 빈 stub duckdb로 조용히 폴백해 실제로는 빈 결과만 내는 상태였다(숨은 버그).** `read_sql_pg()`(PG_DSN, `mineral_risk` 스키마)로 전환해 해결, "니켈 현재 수급위기 등급" 질의로 `structured=True` 라우팅→정상답변 end-to-end 확인. 단 PG `mineral_risk` 스키마는 실시간 동기화가 아님 — `geo_index`가 라이브 대비 약 1주 stale(운영 전 정기동기화 여부 결정 필요, §3 표 추가 참고) |
| 2-2 문서검색 | **구현됨**(이번 세션 개선) | dense(pgvector)+BM25(Postgres FTS) RRF 하이브리드 + PageIndex(simple: find_documents/search_nodes/read_node_text) |
| 2-3 원인해석(혼합형) | **부분 구현 — 실측 미검증** | `RetrievalRoute`가 `use_structured`/`use_dense`/`use_pageindex`를 각각 독립 플래그로 둬 구조적으로는 동시 조회 가능(ThreadPoolExecutor 병렬). 다만 이번 세션 3회 테스트 전부 dense 단일경로만 트리거됨 — 라우팅 LLM이 실제로 "정형+비정형 동시조회"를 판단해 켜는지는 검증된 사례 없음 |
| 2-4 비교질문 | **구조적 한계 있음** | `RetrievalRoute.commodity_code`가 **단일값**(`Literal["CU","NI","CO","LI","REE"] | None`) — 정형 도구(`structured.py`)가 한 턴에 광종 1개만 조회 가능. "리튬과 니켈 비교"류는 dense 검색이 우연히 두 광종을 언급한 문서를 찾아야만 답변 가능(구조적 지원 아님) |
| 2-5 메뉴안내 | **구현됨(별도 서브시스템)** | `page_recommend/`(43페이지 레지스트리) — document 경로가 아니라 intent.py가 분리한 별개 경로 |
| 2-6 범위밖질문 | **부분 구현 — 요구사항 미달** | `generate.py SYSTEM_PROMPT`의 `ABSTAIN_TEXT="제공된 문서에서 근거를 찾지 못했습니다."`뿐 — 투자조언 등 범위외 질문도 "근거 없음"과 동일하게 처리돼 **B안이 요구하는 "제공가능범위 안내"가 없음**(예시: "투자 조언은 제공하지 않습니다. 대신 니켈 가격·수급 지표는 안내해드릴 수 있습니다." 같은 문구 미구현) |

### 2-3. 세부옵션 대응
| 항목 | 확정안 | 구현 상태 |
|---|---|---|
| 데이터 표출 | C안(텍스트+표+그래프) | **일치** — `chatbot_events.py`(`extract_markdown_tables`+`render_chart_png`)가 인용된 근거에 표 있으면 table 이벤트, 완전한 숫자열이면 즉석 차트 image 이벤트 |
| 출처 표기 | C안(버튼→패널) | **백엔드 데이터는 구비, UI 렌더링은 프론트 몫** — `done` 이벤트가 `citations: [{index,kind,source,section,as_of,unit}]` 구조로 반환(패널 렌더링에 필요한 정보는 다 있음), 실제 버튼/패널 UI는 이 저장소 범위 밖(프론트 별도 개발) |
| 관련메뉴 연결 | A안(텍스트 경로만) | **page 경로 응답 형식 확인 필요** — `page_recommend`가 실제 URL을 포함하는지, "상세링크는 추가"라는 부가조건이 반영됐는지 미확인 |
| 질의응답 턴수 | B안(무제한) | **절충 구현** — `chatbot_store`는 세션·메시지를 무제한 저장하지만, `MAX_HISTORY_MESSAGES=12`(최근 6턴)만 프롬프트에 실음(토큰 예산 때문에 불가피). "세션 내 기록 제한 없음"의 의미가 저장 무제한인지 프롬프트 컨텍스트도 무제한인지 발주처 확인 필요 |
| 대화 어투 | A안(격식체) | **미구현** — `SYSTEM_PROMPT`에 어투 관련 지시문이 전혀 없음(인용규칙만 있음), 실제 응답 어투는 로컬 LLM 기본값에 의존(이번 세션 테스트 응답들은 우연히 격식체에 가까웠으나 프롬프트로 강제되는 게 아님) |
| 도입부 예시질문 | A안(고정 3~5개) | **백엔드 미구현** — 코드 전체에 추천질문/예시질문 관련 로직·API 없음(순수 프론트 영역일 수 있음, 확인 필요) |
| 진입위치 | 미확정 | 해당 없음(프론트/IA 결정사항, 백엔드 무관) |

### 2-4. 요구사항에 없던 추가 구현(기획서 대비 확장)
- **agentic PageIndex 순회**(`pageindex_agent.py`): "니켈 다음으로 몇 번째로 캐는 나라는?" 류
  국가별 순위·집계 질문 — 기획서 시나리오엔 명시 안 됐지만 2-3(원인해석)/2-2(문서검색)의
  자연스러운 확장으로 이번 사용자 요청("꼬리질문 체인으로 될 때까지 검증")에 따라 구현.
- **verify→reformulate 루프**: 1차 검색이 불충분하면 LLM이 스스로 재질의(최대 1회 재시도,
  `MAX_ATTEMPTS=2`) — 기획서엔 없는 자기검증 메커니즘, 실사용 테스트에서 실제로 답변 품질을
  끌어올린 사례 확인(코발트 DRC 질의).
- **날짜인식 하이브리드 검색**(이번 세션, A+D): 기획서 요구사항엔 없으나 실사용 중 발견된
  결함(최신 연도 질의 기권) 대응.

## 4. 결론

핵심 4시나리오 중 **2-1(통계조회)·2-2(문서검색)·2-5(메뉴안내)는 구현 완료**, **2-3(원인해석)은
구조는 있으나 실동작 미검증**, **2-4(비교질문)는 구조적 공백**, **2-6(범위밖질문)은 확정 요구사항
(B안) 대비 미달**로 정리됩니다. 세부옵션 중 데이터표출(C안)·출처표기 백엔드 데이터는 잘
갖춰져 있고, 어투(A안)·범위밖안내(B안)는 프롬프트 보강이 필요합니다. 우선순위는 위 표
1(범위밖질문)·3(비교질문) 순으로 제안합니다 — 둘 다 발주처 확정 요구사항(B안) 미달 또는
시나리오 자체의 핵심 기능 공백이라서입니다.
