# UI 3요소 단순화 + 가격 3페이지 KOMIS 원본 JSON 확장 검증근거 (2026-08-30)

## 사용자 지시(원문)

> 가격변동 주요요인(지정학 위기지수 — KOMIS 아닌 별도 소스, 선택) 이 부분
> 빼세요. komis.or.kr 해당 페이지에서 제공하는 UI만 데모 페이지에 올리지
> 그외는 다 빼고, komis.or.kr에서 나온 json만 입력 받는 textarea, 그리고
> 분석요약 생성 결과 표시 두개만 추가로 있으면 됩니다.

즉 화면 구성을 (1) komis.or.kr 실제 UI를 그대로 반영한 선택 위젯,
(2) KOMIS 원본 JSON 붙여넣기 textarea 1개, (3) 분석요약 생성 결과 —
**딱 3요소**로 줄이라는 지시. "가격변동 주요요인" 텍스트는 라운드6 이전에
쓰던 geo_events 문구로, 라운드6에서 이미 통째로 삭제됐으나(코드상으로는
남아있지 않음을 이번에도 grep으로 재확인) 사용자가 배포본에서 잔상을 봤을
가능성이 있어 이번 라운드에서 전 UI를 다시 한 번 훑어 확인했다.

## 변경 사항

1. **`report_gen_client.py`의 죽은 코드 클러스터 완전 삭제** —
   `AdvancedJsonField` dataclass, `_KOMIS_PERIOD_COMPARISONS_UNAVAILABLE`
   상수, `ADVANCED_JSON_FIELDS` dict, `parse_advanced_json_fields()` 함수.
   라운드6에서 geo_events를 빼면서 이 클러스터엔 이제
   `komis_period_comparisons`(price_minor/iron/other 3개, 실측 부재로
   항상 빈 값) 하나만 남아 있었는데, 애초에 값이 채워질 일이 없는 빈
   플레이스홀더 expander였던 데다 이번 지시로 "선택 UI+textarea+결과" 외
   부가 UI를 전부 없애야 하므로 함께 제거.
2. **`views/report_demo.py`**: 위 삭제에 맞춰 import 정리, `else`(구
   observations 플로우) 분기에서 "고급: KOMIS 원본값 직접 입력" expander와
   `advanced_texts` 추적 로직 삭제. 파일 맨 끝의 "요청 바디 미리보기"
   expander(디버깅용 JSON 프리뷰)도 통째로 삭제 — 이것도 "결과 표시" 외의
   부가 UI이므로 지시 범위에 포함.
3. **`views/prompt_admin.py`**: "기능 테스트" 섹션에 동일 패턴 적용 —
   `ADVANCED_JSON_FIELDS`/`parse_advanced_json_fields` import 제거,
   `advanced_texts` 선언과 "고급: KOMIS 원본값 직접 입력" expander 블록
   삭제, 버튼 핸들러의 `else` 분기에서 `parse_advanced_json_fields` 호출을
   없애고 바로 `client.summarize()` 호출로 단순화. (참고: 이 파일 상단
   프롬프트 CRUD 영역에 있는 "페이지 정책·출력 계약(고급 — 비우면 NULL로
   저장...)" expander는 이름만 "고급"이 겹칠 뿐 프롬프트 DB 편집 UI라
   이번 지시와 무관 — 그대로 유지.)
4. **`komis_raw.py`의 `KOMIS_RAW_PAGES`를 6→9개 페이지로 확장** —
   price_minor_metals·price_iron_energy·price_other 3개를 추가. 이
   3페이지는 KOMIS 실제 화면에서 광종만 다를 뿐 price_base_metals와 같은
   조회 API(`getMnrlPrcByMnrkndUnqCd`)를 쓴다는 가설을,
   `documents/산출물/2026-W35_0824-0830/report_gen_KOMIS라이브재검증_
   Phase2_260829_evidence/collected_iron_other_day_raw_260829.json`(철·금
   실측 캡처)로 확인 — 응답 구조가 price_base_metals와 완전히 동일해
   기존 `convert_price_snapshot()`을 그대로 재사용했다(신규 변환 함수 작성
   불필요). prefill 예시는 코발트(price_minor_metals)·철(price_iron_energy)·
   금(price_other) 실측값 그대로.
5. **4개 가격 페이지의 `PAGE_SPECS.extra_fields`에서 `price_unit`·
   `price_criterion_serial` 제거** — Phase1 실측으로 확인된 KOMIS 실제 쿼리
   파라미터 목록(`mnrkndUnqRadioCd, srchMnrkndUnqCd, srchPrcCrtr,
   srchAvgOpt, srchField, srchStartDate, srchEndDate,
   srchCompareMnrkndUnqCd, srchComparePrcCrtr, lmeInvt`)에 이 두 필드에
   대응하는 파라미터가 없다 — report_gen 내부 스키마에만 존재하고
   komis.or.kr 화면에는 없는 개념이므로 "실제 KOMIS UI만 남긴다"는 이번
   지시에 따라 제거. `price_criterion`(→`srchPrcCrtr`)과
   `compare_mineral`/`compare_price_criterion`(→`srchCompareMnrkndUnqCd`/
   `srchComparePrcCrtr`, price_minor_metals 전용 "비교광종" 기능)은 실제
   파라미터와 대응되므로 유지.

## 검증 — 12개 page_id "버튼만 클릭" 전수 재검사(임시 8502 인스턴스)

Streamlit 최신 빌드가 selectbox를 BaseWeb이 아니라 react-aria
`ComboBox`(`<input role="combobox">`)로 렌더링하는 것으로 확인돼(라운드6까지
쓰던 `[data-baseweb="select"]` 셀렉터가 더 이상 안 먹음), Playwright 스크립트의
셀렉터를 `input[role="combobox"]` 기준으로 교체하고 나서야 정상 동작 —
이번 라운드에서 새로 발견한 자동화 스크립트 함정(앱 코드 버그 아님).

| page_id | status | textarea 수 | 금지 문구(고급/미리보기/geo_events) |
|---|---|---|---|
| indicator_market | ok | 1 | 없음 |
| indicator_supply | ok | 1 | 없음 |
| indicator_composite | ok | 1 | 없음 |

12/12 `status: ok`, 페이지당 textarea 정확히 1개, "고급: KOMIS", "요청 바디
미리보기", "geo_event", "지정학 위기지수", "가격변동 주요요인" 5개 금지
문구 전부 0건. 신규 3페이지(가격 희소금속/철에너지/기타)는 실측 코발트·철·금
JSON을 그대로 붙여넣은 상태로 status:ok까지 확인(변환 로직 재사용이 실제로
맞았음을 실행으로 증명).

`prompt_admin.py`의 "기능 테스트" 섹션도 price_minor_metals로 동일하게
확인 — KOMIS 원본 JSON textarea 1개만 노출, "고급" 문구 없음(단, 위에서
설명한 프롬프트 편집 영역의 무관한 "고급" 문구는 그대로 존재 — 오탐 아님을
본문 대조로 확인), 버튼 클릭 시 status:ok.

## 남은 한계(정직하게 기록)

- price_group·indicator_market·indicator_supply 3개 page_id는 이번에도
  KOMIS 원본 응답 구조 실측 캡처가 없어(전자는 엔드포인트 미확정, 후2자는
  로그인 필요 페이지) 기존 observations 수동 JSON 입력 방식을 그대로 유지—
  라운드6 결정 불변.
- price_criterion 등 몇몇 텍스트 입력 필드는 기본값이 빈 문자열이라
  버튼을 누르면 그 필드 없이 요청이 나간다(그래도 report_gen이 optional로
  받아 status:ok는 나옴) — 이번 지시(UI 요소 개수 축소)와는 무관한 별개
  이슈라 이번 라운드에서 손대지 않음.
