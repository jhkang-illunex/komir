# 신규 필드 전달 통로 추가 + 검증근거 (2026-08-29)

main-agent 지시(2026-08-29) — "값을 지어내지 말고 나오는 값만 제대로 전달하면 된다"는
원칙에 따라 report_gen의 오늘 신설 필드(inventory·is_actual·geo_events·
komis_period_comparisons·komis_trade_totals)를 데모가 그대로 전달할 수 있게
`report_gen_client.py`/`report_demo.py`/`prompt_admin.py`에 통로만 추가했다. 검증은
임시 8502 인스턴스(운영 8501·공유 컨테이너 미접촉)로 실제 재현.

## 빠른 수정(기존 예시 JSON)

1. price 4종(`price_base_metals`/`price_minor_metals`/`price_iron_energy`/
   `price_other`) `observations_example`에 `inventory: 15000.0` 추가.
2. `forecast_price` `observations_example`에 `is_actual` true/false를 섞음.
   ⚠ 최초 시도(2개 관측치, 1개만 true)는 계산기가 `is_actual=true` 관측치를 예측
   요약에서 제외하는 서버 로직(`models.py` 확인) 때문에 예측치가 1개만 남아
   NO_DATA로 **회귀**했다 — 3개(실측 1 + 예측 2)로 확장해 해결(직접 재현으로 발견,
   전체 12개 재검사 스윕에서 잡힘).
3. `map_korea`: `trade_direction=수출` 선택 시 observations 예시가 `export_weight`/
   `export_amount` 필드로 동적 전환되도록 `MAP_KOREA_OBSERVATIONS_BY_DIRECTION` 추가.

## 신규 위젯 — "고급: KOMIS 원본값 직접 입력(선택)" expander

- price 4종: `geo_events`(리스트)·`komis_period_comparisons`(객체) JSON 입력란.
- map_korea/map_global: `komis_trade_totals`(객체) JSON 입력란.
- 전부 기존 `observations` textarea와 같은 패턴(자유 JSON 입력, 비어있으면
  payload에 안 넣음, 파싱 실패는 `render_json_error`로 안내). 값을 지어내는
  로직은 전혀 없음 — `parse_advanced_json_fields()`가 입력을 그대로 `json.loads`해
  전달만 한다.
- placeholder는 `models.py`의 실제 pydantic 필드(`GeoEventObservation`·
  `PriceKomisPeriodComparisons`·`TradeKomisTotals`)에 맞춘 구조적으로 올바른
  예시(값 자체는 report-summary-agent의 실측 캡처를 못 받아 직접 구성 — 형태는
  스키마와 100% 일치, 숫자는 임의).

## 검증 — 12개 page_id 회귀 + 신규 필드 실제 반영 확인

**회귀 스윕**: 8502에서 12개 page_id 전부 기본 버튼 클릭 재실행 →
`indicator_composite` 1건만 여전히 NO_DATA(오늘 변경과 무관, 기존부터 있던
별개 이슈로 이전에 보고 완료)이고 나머지 11개는 status:ok. `map_mineral`은
라운드2 수정이 여기서도 반영돼 ok, `forecast_price`는 위 §2 문제를 고친 뒤 ok.

| 검증 항목 | 방법 | 결과 |
|---|---|---|
| `inventory` | price_base_metals 기본 예시(버튼만 클릭) | 리포트에 "재고량은 15,000.00" 명시 — 반영 확인. 스크린샷 02 |
| `is_actual` | forecast_price 기본 예시(2026-Q1 실측/Q2·Q3 예측) | 리포트가 "첫 예측시점인 2026년 2분기"로 시작 — Q1(실측)이 예측 요약에서 정상 제외됨 확인. 스크린샷 01 |
| `komis_period_comparisons` | 고급 expander에 채워 제출 | 리포트에 "전주평균(9,700.00) 대비 +0.98%… 전월평균… 전년평균…" 명시 — 반영 확인. 스크린샷 04 |
| `komis_trade_totals` | map_korea 고급 expander에 채워 제출 (UI) + 동일 payload를 curl로 직접 호출 (API) | 관측치 합산 850,000→진짜총액 1,250,000로 교체, 1위국 비중도 100%→68%로 재계산 — UI·API 양쪽에서 동일하게 확인. 스크린샷 06 |
| map_korea 수출 예시 동적 전환 | trade_direction 셀렉트를 수출로 전환 | observations 텍스트가 `export_weight`/`export_amount` 필드로 즉시 전환 확인. 스크린샷 05 |
| prompt_admin.py 동일 기능 | 기능테스트 섹션에서 map_korea + komis_trade_totals 동일 재현 | report_demo.py와 동일하게 1,250,000 반영 확인 |

## 참고 — geo_events는 서버 응답에 아직 반영되지 않음(코드 결함 아님, 참고 보고)

`geo_events`를 UI로 채워 제출했을 때 리포트 서술(핵심 진단·주요 변화 등)에 "칠레"·
"파업"·"공급" 등 관련 문구가 전혀 나타나지 않았다. 동일 payload를 curl로 직접
호출해도 결과가 동일해(데모 쪽 전달 문제 아님을 확인) — 서버가 `geo_events`를
받아들이기는 하지만(422 없음) 이 데이터 형태(단일 관측치+단일 이벤트)에서는 아직
서술에 반영하지 않는 것으로 보인다. report_gen 서버 로직 확인은 제 담당 범위
밖이라 report-summary-agent 쪽 확인이 필요해 보여 참고로 남긴다(수정은 안 함).
