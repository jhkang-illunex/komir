# UI/UX 감사 라운드1 — 수정 + 실측 검증 근거 (2026-08-28)

대상 파일: `inhouse/streamlit_demo/views/report_demo.py`·`views/prompt_admin.py`·
`report_gen_client.py` (`worktree-streamlit` 브랜치, 커밋 예정).

**검증 방법**: `komir-report-gen-test`(:18003, 공유)·8501 운영 streamlit 프로세스는 다른
세션이 관리 중이라 건드리지 않았다. 대신 이 워크트리의 수정된 코드를 **임시로 8502
포트에 별도 기동**해 Playwright로 재현 시나리오를 실제로 다시 실행하고 수정 전/후를
대조한 뒤, 검증이 끝나자마자 8502 인스턴스를 종료했다(운영 8501·공유 컨테이너에는
영향 없음). DB는 이전 감사와 동일하게 "내용 동일 재저장"만 실행했고, 저장 전후
`output_contract` 값이 그대로임을 DB 직접 재조회로 재확인했다(`indicator_market`
행 — `updated_at`만 갱신).

## 1. [P0] 파싱 실패 후 이전 리포트 잔존 — 수정 확인

- **재현**: 정상 제출(`screenshots/라운드1_수정검증/A2_...png`, status: ok + 리포트 정상
  표시) → observations를 깨진 JSON으로 바꾸고 재제출.
- **수정 전(감사 시점)**: 에러 배너 아래에 직전 리포트 전문이 그대로 남음
  (`screenshots/09_P0_에러아래_이전리포트잔존버그.png`).
- **수정 후**: `screenshots/라운드1_수정검증/A3_P0수정확인_에러후이전리포트안남음.png` —
  에러 배너만 남고 "핵심 진단" 등 이전 리포트 텍스트가 전혀 없음. 본문 텍스트 검색으로
  `"핵심 진단" in body` → `False` 확인(스크립트 출력 로그 동봉 가능).

## 2. [P1] JSON 파싱 원시 예외 노출 — 수정 확인

- **수정 후**: `observations JSON 형식이 올바르지 않습니다 — 쉼표·따옴표 등을
  확인하세요.` 한 줄 요약이 먼저 뜨고, 원본 Python 예외는 `원본 오류 메시지(디버깅용)`
  expander로 접힘. report_demo.py(A3 스크린샷)·prompt_admin.py 양쪽에서 동일하게
  확인(`screenshots/라운드1_수정검증/B2_output_contract_친화적에러+원문접기.png`).
