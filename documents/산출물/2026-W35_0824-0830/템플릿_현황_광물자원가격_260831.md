- `price_criterion`/`compare_price_criterion`(선택, 자동채움: `dataAvg.INFO.prcCrtr` / `dataAvg.cmpMap.INFO.prcCrtr`).
- `komis_response`(선택이지만 사실상 필수 — 이 필드 없이는 관측치 자체가 없어 NO_DATA) — KOMIS `getMnrlPrcByMnrkndUnqCd` 원본 응답을 그대로 받는다.

**결정론적 문장 템플릿**(`komir_summary.py::calculate_price_summary`, 조건별로 근거(EvidenceClaim)가 붙거나 빠진다):

- **core_diagnosis** (`current_state`, 필수 1개):
  `"{일자} 기준 {광종명} 실거래가는 {가격}이다."`

- **major_changes** (조건별 최대 5개, `_MAJOR_CHANGES_HARD_CAP`):
  1. `day_over_day`(전일/직전 관측치 대비, 이전 관측이 있으면):
     `"{전일(날짜) 또는 직전 관측치(날짜)} 대비 {부호등락률}% 변동했다."`
     — 직전 관측일이 정확히 하루 전이면 "전일", 아니면 "직전 관측치"(간격이 넓은 조회에서 오해 방지).
  2. `week_avg`/`month_avg`/`year_avg`(전주·전월·전년 평균 대비, KOMIS 제공값이 있으면 그 값을 우선, 없으면 자체 롤링윈도우 재계산):
     `"{전주평균/전월평균/전년평균}({평균값}) 대비 {부호등락률}% 수준이다."`
     — 관측이 희소해 여러 기간이 같은 관측 윈도우로 수렴하면 짧은 기간만 남기고 중복 생략.
  3. `price_streak`(연속 2회 이상 같은 방향일 때만):
     `"{N}{일/주/월} 연속 {상승세/하락세/보합세}를 보이고 있다."`
  4. `period_overall_change`(2026-08-31 신설, 자리가 남으면 — 새 데이터소스 없이 조회기간 시작 대비):
     `"조회기간 시작({날짜}, {가격}) 대비 {부호등락률}% 변동했다."`
  5. `price_driver_event_1`/`_2`(geo_events 요청 필드가 있을 때만, PDF의 "가격 변동의 주요 요인" 대응):
     `"조회기간 중 {국가}에서 {공급 감소/공급 증가/가격 상승/가격 하락/수요 감소/수요 증가/동향 변화} 흐름과 맞물린 사안이 있었다({날짜} 기준)."`(+ 품질 통과 시 보도 인용 덧붙임)
     — ⚠ **이 세션(report-summary-agent) 초기 지시로 geo_events는 API 입력 데이터에서 제외됐다 — 현재 이 근거는 사실상 항상 비어 있다.**

- **current_position** (조건별 최대 3개):
  1. `period_range`(최고/최저가 커버리지 완전하면 hilo, 아니면 실거래가 기준으로 폴백):
     `"조회기간 중 최고 {값}({날짜}), 최저 {값}({날짜})였다."`
  2. `inventory_level`(재고량이 0/None이 아닌 관측이 있으면, LME 6대 비철금속 외엔 대개 없음):
     `"{날짜} 기준 재고량은 {값}이다. {전일/직전 관측치 대비} {부호등락률}% 변동했다."`
  3. `compare_overall_change`(비교광종 지정 시): `"같은 조회기간 동안 {비교광종}은 {부호등락률}% 변동한 반면, {광종}은 {부호등락률}% 변동했다."`

**LLM 정제 지시문 핵심**(`prompts.py::PRICE_SUMMARY_INSTRUCTIONS`):
- 등급·단계 없음, 실거래가+등락만 다룬다.
- major_changes는 있는 비교 기간만 이어 쓰고 없는 기간을 만들어 채우지 않는다(최대 근거 5개까지 한 문장에 묶을 수 있음, `max_evidence_ids_per_sentence=5`).
- `price_driver_event_*` 근거가 없으면 원인(수급 이슈·환율·지정학 등)을 절대 추정하지 않는다.
- 예측이 아니라 실측이므로 "확정된 사실"로만 쓰되, 등락 원인은 근거 문장을 그대로 옮기고 "때문에"·"영향으로" 같은 인과 단정 표현으로 바꿔쓰지 않는다("맞물린" 톤 유지).
- 재고량 근거가 있으면 단위·거래소명을 새로 지어 붙이지 않는다.

### price_group

**요청 입력**(`PriceGroupSummaryRequest`): `price_group`(필수, `"base_metals"`|`"minor_metals"`), `observations`(선택 — `PriceGroupMineralObservation` 리스트: `mineral_name`·`week_change_pct`·`month_change_pct`). ⚠ 이 페이지는 komis_response를 지원하지 않는 9개 페이지 목록 밖이라 여전히 손 매핑 `observations`만 받는다 — 이미 계산된 광종별 등락률을 캐스터가 직접 넣어야 한다(개별 광종 원자료가 아님).

## 원본 템플릿과의 차이·특이사항(사실만, 평가 없음)

1. **PDF는 "전년 동기" 비교까지 요구**(1-1) — 구현은 `전년평균`(365일 롤링 평균) 대비로, "전년 동기(같은 날짜)"가 아니라 "최근 1년 평균"이다. KOMIS가 제공하는 `dataAvg.stdMap.YEAR`도 같은 "평균" 개념이라 이 값을 그대로 쓴다.
2. **PDF의 "가격 변동의 주요 요인"**은 코드상 `price_driver_event_*`로 구현돼 있지만, geo_events 입력 자체가 이 세션 초반 지시("geo_events는 안 씁니다")로 API에서 빠져 있어 실제로는 채워지지 않는다.
3. **PDF 1-2(전체광종)의 "주요 요인"(상승/하락 요인)**도 `price_group`엔 아예 없다 — `group_movers`/`extreme_movers`는 "누가 얼마나 움직였는지"만 서술하고 "왜"는 다루지 않는다(제공 데이터 자체가 등락률 숫자뿐이라 원인 서술 근거가 없음).
