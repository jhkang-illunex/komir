## 1. 원시데이터 수집 → ETL → 중간 산출물 (🟢 자동, cron)

정형(관세청·ECOS·KOMIS·거래소)과 비정형(GDELT/GKG 뉴스) 두 계열이 각자 독립된 cron으로 매주/매월
자동 수집·정제되어 같은 운영 DB(`inhouse/data_lake/db/minerals.duckdb`, 구 `warehouse/minerals.duckdb`)에 쌓인다.

```mermaid
sequenceDiagram
    autonumber
    participant Cron as system crontab
    participant GeoColl as dmz/geo_collectors<br/>gkg_bulk_download
    participant GeoParse as inhouse/geo<br/>gkg-parse
    participant LLM as LLM(vLLM, openai_compat)
    participant GeoVerify as inhouse/geo<br/>gkg_verify
    participant MsrColl as dmz/msr_collectors
    participant DB as inhouse/data_lake/db/minerals.duckdb

    rect rgb(235,245,255)
    Note over Cron,DB: 지정학 — 매주 토 06:30 (cron_gkg_increment.sh, 7단계)
    Cron->>GeoColl: [1/7] GKG 벌크 증분 다운로드
    GeoColl->>GeoParse: [2/7] python -m geo gkg-parse --bulk-root
    GeoParse->>DB: geo_event 후보 적재(state 기반 증분)
    Cron->>LLM: 헬스체크(curl)
    alt LLM 응답 실패
        Cron-->>Cron: 이후 단계 전부 스킵, exit 0<br/>(미검증 이벤트 발행 방지)
    else LLM 정상
        GeoVerify->>LLM: [3/7] gkg_verify --limit 0 (전량 재검증)
        LLM-->>GeoVerify: 관련성 판정(채택/기각)
        GeoVerify->>DB: [4/7] compact_event_shards() 샤드 병합
        GeoVerify->>DB: [5/7] --compact-rejections 기각분 실삭제
        GeoParse->>DB: [6/7] geo index && geo prob 재산출
        GeoParse->>DB: [7/7] geo publish --what all → geo_event/geo_index/geo_prob
    end
    end

    rect rgb(245,240,255)
    Note over Cron,DB: 정형 — 매주 토 09:10(weekly)/매월 6일 09:20(monthly) (cron_collect_feeds.sh)
    Cron->>MsrColl: weekly: 거래소재고 증분(SHFE CU/NI·GFEX LI)+COT+해외정책공고
    Cron->>MsrColl: monthly: Comtrade 무역흐름+중국PMI+ISM/유로/부동산+tier1~4 피드
    MsrColl->>DB: fact_* 원시 테이블 upsert(msr/storage/db.py)
    end
```

**중간 산출물**: `geo_event`(검증완료 이벤트 원장), `fact_*`(관세청/ECOS/KOMIS/거래소 원시 팩트) —
아직 모델 입력 형태로 가공되기 전 단계.

## 3. 3대 모델 주기적 갱신

— 지정학위기지수는 §1 cron에 이미 포함되어 완전 자동인 반면, 수급위기진단·수요예측은 담당자가 신규
데이터 도착을 확인한 뒤 수동으로 재학습을 트리거한다(고정 주간 주기 아님, 비정기·실측 트리거 기반).

## 4. RAG 데이터 갱신 (🟡 수동 실행)

RAG는 `documents/산출물/` 하위 md·docx 보고서만 소스로 삼는다(DB 직접 소비 코드는 미확인). 신규
산출물 문서가 추가된 뒤 담당자가 인덱스 재빌드를 수동 실행한다.

```mermaid
sequenceDiagram
    autonumber
    participant Docs as documents/산출물/*.md,*.docx
    participant Op as 담당자
    participant Ingest as ragkit/ingest.py
    participant Chunk as ragkit/chunk.py
    participant Tok as ragkit/tokenize_ko.py
    participant Embed as ragkit/embed.py<br/>(multilingual-e5-small)
    participant Build as ragkit/build_index.py<br/>(오케스트레이터)
    participant Idx as BM25 + dense 인덱스<br/>(현재: 로컬 인덱스 파일)
    participant Gen as ragkit/generate.py<br/>(인용강제+검증게이트)

    Op->>Build: python -m ragkit.build_index (전체 재빌드, 멱등)
    Build->>Ingest: documents/산출물/ md·docx 문서 레코드화
    Build->>Chunk: 마크다운 헤딩 기준 청킹
    Chunk->>Tok: 한글 bigram+영문 토큰 혼합 토큰화(BM25용)
    Chunk->>Embed: dense 임베딩 산출
    Build->>Idx: doc/chunk + BM25/dense 인덱스 갱신
    Note over Op,Gen: 질의 시점
    Op->>Gen: 사용자 질의
    Gen->>Idx: retrieve.py — BM25+dense RRF 하이브리드 검색
    Idx-->>Gen: 상위 청크 반환
    Gen-->>Op: 인용 포함 답변 생성
```

## 6. 자동/수동 경계 요약

- **완전 자동(🟢)**: 지정학위기지수 전 구간(수집→검증→지수화→발행). 정형 데이터 수집(관세청·ECOS 등)도
  cron으로 자동 — 단, 그 데이터를 이용한 **모델 재학습 자체는 수동**.
- **수동이지만 코드 기반 반복 실행(🟡)**: 진단·예측 모델 재학습, RAG 인덱스 재빌드, 신규 피처 검정
  (`r10_retune_harness.py`) — 전부 실제로 반복 사용되는 코드지만 사람이 트리거해야 함.
- **설계만 있고 코드 없음(⚪)**: `dmz/upload_files/` → ETL 자동화, `inhouse/services/ingestion`·
  `inhouse/services/report_gen` 전체. `documents/meta/CONTAINER_ARCHITECTURE.md`에 설계 문서는
  있으나 구현은 다음 세션 이후로 명시적으로 미룬 상태(2026-08-05 확정).
