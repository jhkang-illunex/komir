# 해외 정부기관 수집 요청 리스트 — 항목별 점검 (2026-07-29)

발주처가 지정한 tier1 3개국·tier2 6개국의 국가×기관 리스트를 원 요청 순서
그대로 항목별로 점검한다. 각 항목에 ①수집 가능 여부 ②가능하면 실제 확보한
시계열(코드·단위·기간·행수, 전부 DB 재실측※1) ③불가하면 기술적 사유
④수집을 수행하려면 필요한 조치(가입·API키·유료 여부)를 기술한다. 마지막
장은 "통계적 기각"과 별개로 **애초에 다른 데이터와 행(row)을 맞출 수 없는
구조적 사유**를 모아 설명한다(요청하신 부분).

`해외관세정책_데이터확장_260728.md`(전일 작성)의 상세 버전이자 점검판 —
이번 문서에서 오류·미확정 사항을 바로잡은 곳은 각주로 표시했다.

## 2. 국가별 상세

### 2-1. 중국

**상무부(MOFCOM)** — 가능(구현 완료)
- 시계열: 시계열이 아니라 **이벤트 로그**다. `raw_policy_notice`(src=MOFCOM_ZCFB) —
  수출통제·쿼터·실체명단 공고 제목+일자+URL. 실측 15건(2026-03-20~07-27).
- 수집 방식: 대외무역관리 목록 페이지의 jpaas unit API(GET, 무키).
- 한계: **과거분 백필 불가**(§5-C에서 사유 상세) — 앞으로 주간 폴링 축적만 가능.
- 필요 조치: 없음(이미 무료·무인 가동 중, cron 주간).

**해관총서(GACC)** — 부분 가능(구현 완료)
- 시계열(전부 GACC_EN_MONTHLY, 월간, 2018-01~2026-06):
  - `CN_CU_ORE_IMPORT_QTY/VAL_GACC`(동정광 수입, 87행)
  - `CN_CU_UNWROUGHT_IMPORT_QTY/VAL_GACC`(미가공동 수입, 96행)
  - `CN_REE_EXPORT_QTY/VAL_GACC`(희토류 수출, 97행)
  - `CN_REE_IMPORT_QTY/VAL_GACC`(희토류 수입, 51행 — 월보 표에 2022년부터 등재)
- **니켈·코발트·리튬은 이 경로로 확보 불가**: 영문 월보의 "주요 품목" 표(13·14번)에
  단독 행이 없음(실측 확인 — CU·REE·철광석·알루미늄광·리튬이온배터리만 등재).
- 불가 사유(상세 통계 stats.customs.gov.cn): HTTP 412 + 가속락(JSL) JS 쿠키
  챌린지 — 순수 HTTP 클라이언트로 세션 획득 불가.
- **07-29 headless 우회 실제 시도 → 실패 확정**(Playwright 5단계: 기본
  headless·명시적 재로드·개별 지문패치(navigator.webdriver 등)·
  `playwright-stealth`(표준 라이브러리)·HTTPS 우회 전부 시도). JS 챌린지는
  실행되고 쿠키도 정상 발급되지만 재요청이 매번 400으로 막힘(지문 스푸핑
  수준 대응으로는 동일 결과 재현 — 챌린지 자체가 VM 난독화 봇탐지 코드라
  역공학도 비현실적). HTTPS는 아예 다른 CDN(Yunjiasu)을 타고 504로 막힘.
  상세 로그는 `해외관세정책_데이터확장_260728.md` §8-4.
- 필요 조치(NI·CO·LI 확보하려면): headless 자체구축은 **판정을 "불가"로
  하향**(추가 투자해도 성공 미보장) — 유일한 실행 경로는 GTA/TDM/CEIC 등
  상용 벤더 구독(유료). **발주처 협조 요청 대상은 이 범위로 축소 권고**.

### 2-2. 미국

**상무부(Census Bureau 무역 API)** — 조건부(키 필요)
- 시계열(발급 후 즉시 가능): `api.census.gov/data/timeseries/intltrade/imports·exports/hs`
  — HS10×국가 월별 수출입 금액·물량·**납부 관세액(DUT_VAL_MO)**. 2010-01~ 현재,
  래그 ~5주.
- 필요 조치: `api.census.gov/data/key_signup.html` — 이름·이메일 입력 후 이메일로
  즉시 발급. **무료, 등록만 필요**.

**관세국경보호청(CBP)** — 불가
- 사유: 웹·데이터포털(`cbp.gov/newsroom/stats/*`) 전 경로 HTTP 403. TLS 핑거프린트
  기반으로 추정되는 봇 차단으로 UA 위장으로도 우회 불가. 공개 REST API 없음.
- 대체: 관세율·조치 정보는 아래 2건으로 완전 대체.
  - **USITC HTS 관세율**(가능, 구현 완료) — `raw_hts_rates`, 5광종 HS4+챕터99
    전체(232/301/IEEPA 추가관세 footnote 연결), 775행, 릴리스 `2026HTSRev12`.
    무키·즉시.
  - **연방관보(Federal Register)**(가능, 구현 완료) — `raw_policy_notice`
    (src=FEDREG_API), BIS(수출통제)·USTR(301조) RULE/NOTICE, 1,366건. **현재
    코드는 2020-01-01부터 수집 중이나 이는 임의 설정값**이며, 실제로는
    2002-04-26까지도 조회 가능함을 재확인(2016년 한 해만 131건 확인). 과거
    이력이 필요하면 시작일 파라미터만 바꾸면 됨 — 기술적 제약 아님.

**관세청** — 조건부(키 필요)

- 시계열: `webapi.bps.go.id` — HS별 월별 수출입(니켈 광석 HS 2604 등 포함
  가능, 실호출로 엔드포인트 생존 확인·키 게이팅만 확인).
- 필요 조치: `webapi.bps.go.id/developer/register` — 이메일 2개 필드만 입력,
  키 2~3개 발급. **무료**.

### 2-4. 아르헨티나 (리튬)

**에너지부(광업차관실)** — 조건부
- 시계열: 월간 리포트 PDF(수출액·주별 원산지 등, 광종 대분류 수준).
- 한계: 문서명 패턴 불안정 + **PDF가 스캔본일 가능성**(WebFetch 텍스트 추출
  실패 실측) → OCR 필요할 수 있음. §5의 그레인 이슈에도 해당(연·월 혼재).

**관세청(ARCA, 구 AFIP)** — 가능(구현 완료, 2026-07-29 당일)
- 시계열: `AR_LI_EXPORT_WGT_ARCA`(수출 물량 kg)·`AR_LI_EXPORT_VAL_ARCA`
  (수출 금액 USD), NCM `2836.91`(탄산리튬) 기준, 월간, **2019-01~현재**.
  상세는 §6.
- 수집 방식: `afip.gob.ar/operadoresComercioExterior/informacionAgregada/
  download.aspx?filename=YYYYMM.zip` — URL 연월 완전 예측. zip 안의
  "Total Exportación" 파일(9컬럼, 공식 안내 PDF로 컬럼 확인)만 파싱, 같은
  zip의 수입 파일(월 6GB급)은 제외.
- **리튬을 직접 집계하는 아르헨티나 관세청 유일 정형 경로** — 기존 채택
  피처(아르헨 LI z24)는 Comtrade 산발 보고(56/123개월)이므로 이걸로
  보완·교차검증 가능. R10 재검정 대상(§6).
- 필요 조치: 없음(무키, 구현 완료).

### 2-5. 칠레 (동·리튬)

**관세청(Aduanas)** — 보류(구현 안 함, 사유 확인됨)
- 실제로 받아본 결과 datos.gob.cl CKAN 경유 파일은 **건별(transaction-level)
  원자료**(1개월 텍스트 44MB, 헤더 없음, `;` 구분 84필드)이고, CKAN에 함께
  걸린 "메타데이터" xlsx는 **수출(DUS)이 아니라 수입(DIN) 컬럼 설명서**였다
  (시트명 자체가 "DIN"). 즉 우리가 쓸 수출 파일의 84개 필드 중 어느 것이
  관세코드·중량·금액인지 공식 문서가 없다 — 표본 1행에서 69번째 필드가
  관세코드로 보이나(예: `76129000`=알루미늄캔, 상품명과 일치) 공식 확인
  불가. 추측만으로 구현하면 값이 조용히 틀릴 위험이 있어(§careful-code
  원칙) **이번엔 구현하지 않음**. 상세는 §6.
- 필요 조치: 없음(무키) — 단 (a) 진짜 DUS 필드 설명서를 찾거나 (b) 여러
  표본월을 놓고 필드값을 역산(가격대·물량대 비교)해 검증 완료해야 착수 가능.

**광업부(COCHILCO)** — 가능(기왕 구현, 2026-07-25~)
- 시계열: `CL_CU_PROD_MINE`·`CL_CU_PROD_REF`(광산생산·정련생산, 각 137행,
  2015-01~2026-05).
- 한계: **리튬은 정형 통계가 없음** — Cochilco 리튬 자료는 시장분석 PDF뿐.
  Sernageomin(광업 통계기관)도 과거 리튬 생산량을 포함한 연차보고서를
  발행하나 97MB 단일 PDF(OCR 필요) — §5 그레인 이슈.

### 2-6. 콩고민주공화국 (동·코발트)

**광업부** — 불가
- 사유: 부처 사이트(mines.gouv.cd) 전역 **HTTP 500**(서버 장애로 추정, 구글
  스니펫엔 수치 노출되는 걸 보면 정상 시엔 콘텐츠 존재). CTCPM(광업기술조정처)은
  루트는 살아있으나 통계 카테고리 페이지 404, 개별 PDF 링크는 하드코딩해야만
  접근 가능. 중앙은행(BCC)은 TLS 인증서 체인 오류로 접근 불가.
- 대체(기왕 확보): 중국 측 수입 신고를 미러로 사용 — `CN_CO_IMPORT_COD_WGT`
  (UN Comtrade, 중국의 對DRC 코발트 중간재 수입, 108행, 2016-01~2024-12).
  DRC 자체 신고가 아니라 **상대국(중국) 신고 기준**이라는 한계는 있음.
- 필요 조치(개선하려면): UN Comtrade 정식 무료 키(§3) 발급 시 잠비아·벨기에·
  남아공 등 경유국 미러로 확장해 교차검증 가능.

### 2-7. 페루 (동)

**에너지광물부(MINEM)** — 조건부
- 시계열: 월간 볼레틴(생산량 등, PDF).
- 사유: gob.pe 도메인 전역 **HTTP 418**(봇 차단, UA 위장 미검증이라 "불가"
  아닌 "미확인"으로 분류) + 파일 ID가 월과 무관한 난수라 URL 예측 불가(목록
  페이지 파싱 선행 필요).
- **생산량은 이미 대체 확보됨**: `PE_CU_PROD_MINE`(BCRP 경유, 317행,
  2000-01~2026-05) — MINEM 원자료를 BCRP가 재배포.

**관세청(SUNAT)** — 불가(직접) / 대체로 해소
- 사유: 자체 통계 페이지가 **2017~2018년에서 정지된 레거시**, 다수 링크 파손

## 4. 통계적 기각 — 어제 R10 하네스 검정 결과(참고, §5와 구분)

당일 신규 확보 8개 시계열은 전부 월간 그레인으로 **기존 패널과 행 정합에는
문제가 없었다**. 다만 진단 Δ 모델 검정(부트스트랩, 채택 기준=신뢰구간 하한>0)
에서:

| 후보 | 결과 |
|---|---|
| ph_psa(필리핀 NI, PSA)·au_cu·au_ni | 스크리닝 유망 → 부트스트랩에서 **방향긍정 보류**(신뢰구간이 0을 포함 — 통계적으로 무차별) |
| pe_cu_x·pe_cu_p(페루 CU)·gacc_cu·gacc_cuw·gacc_ree | 스크리닝 단계에서 기존 챔피언 대비 개선폭 미미로 기각 |

이건 데이터를 못 합쳐서가 아니라, **합쳐서 검정해봤더니 기존 가격·재고
피처가 이미 담고 있는 정보와 겹쳐 통계적으로 새로운 설명력이 없었다**는
뜻이다. 아래 §5는 이와 별개로, "합치는 것 자체가 안 되는" 구조적 사유다.

## 5. "다른 데이터와 행(row)을 맞출 수 없는" 구조적 사유

이번 조사 대상 중 상당수는 R10 통계 검정까지 가지도 못했다. 우리 진단모델
패널은 **주간**(`mart_weekly_diagnosis`, Monday 앵커), 예측모델 패널은
**월간**(`mart_monthly_forecast_input`)이 기준 그리드다. 아래 유형은 이 그리드에
행을 채울 수 없거나, 채워도 의미가 왜곡되는 경우다.

**(A) 그레인이 너무 성글다 — 연간·분기 발표를 주간/월간에 강제로 채우면
    허위 정밀도가 생긴다**
- SERNAGEOMIN(칠레) Anuario — 연 1회. 이걸 52주에 그대로 forward-fill하면
  "매주 값이 갱신되는 것처럼" 보이지만 실제 정보는 연 1회뿐이라 진단모델이
  존재하지도 않는 주간 변동을 학습하게 된다(허위 신호).
- 호주 DISR REQ — 분기 발표. 월간 예측 패널에 넣으려면 3개월에 1번만 갱신되는
  값을 나머지 2개월도 동일값으로 채워야 하는데, 이는 사실상 "3개월마다 계단식
  으로 바뀌는 상수"를 넣는 것과 같아 월별 변화를 설명하는 피처로 작동하지 않는다.
- ITIE-RDC(DRC) EITI 보고서 — 연 1회, 그마저도 **발행 지연이 약 2년**(2023
  회계연도 보고서가 2025-12 발행). 진단 패널의 "발표 시점(as-of)" 자체가
  관측 시점보다 2년 뒤라, 실시간 경보에 결합하면 미래 정보 누수(look-ahead)가
  생긴다 — 사후 검증용으로만 쓸 수 있고 피처로는 원천 불가.

**(B) 발표가 "누계"뿐이고 "당월치"가 없다 — 차분해도 결측이 남는다**
- 중국 GACC 월보는 1~2월을 합산 발표한다. 우리 수집기는 2월치를 "누계−1월"로
  복원하지만, 이건 그 해 1월치가 이미 확보돼 있을 때만 가능하다. 연도 경계
  (예: 전년 12월→금년 1월)에서는 전년 누계를 못 구해 복원이 끊기고, 그 지점은
  결측으로 남는다 — 시계열에 "일부러 뚫린 구멍"이 주기적으로 생기는 구조다.

**(C) 조인 키(join key) 자체가 해마다 바뀐다**
- 필리핀 PSA와 GACC는 상품코드 체계가 **연도별로 다른 내부 키**를 쓴다(PSA는
  같은 HS 2604가 연도마다 다른 내부 코드 `26040000001` 식으로 매핑되고, 코드
  집합 자체도 연마다 달라짐 — 실제로 이번 구현에서 연도별로 코드를 다시 조회
  해야 했다). 광종을 코드로 고정 매핑해 여러 해를 이어붙이는 표준적인 방법이
  통하지 않아, 매 연도 메타데이터를 다시 조회하는 비표준 파이프라인이
  필요했다(이번엔 해결했지만, 다른 국가 소스도 같은 문제를 가질 수 있다).
- 아르헨티나 ARCA도 같은 유형으로 확인됐다(§6-1) — 리튬 NCM 코드가
  2017~2018년엔 존재하지 않다가 2019년부터 등장. 국가 자체 품목분류가
  개정되면 옛 시점 데이터를 "찾아서 이어붙이는" 게 아니라 **애초에 그
  코드로는 존재하지 않는다** — PSA·GACC와 달리 이번엔 대체 코드를 찾지
  못해 백필 시작점을 2019-01로 못박는 것으로 대응했다(§6-1).

**(D) 국가가 애초에 신고하지 않는다 — 합칠 "행"이 존재하지 않는다**
- DR콩고 자체 통계, 러시아 니켈(제재 후), 잠비아 코발트(미보고)는 위 (A)~(C)
  와 달리 **그레인·키의 문제가 아니라 원본 자체가 없다.** 이런 경우 유일한
  해법은 상대국(수입국) 신고를 미러로 쓰는 것이고, 이미 CN_CO_IMPORT_COD로
  이렇게 대체하고 있다 — 단 원산지 자체 신고가 아니라는 한계는 남는다.

**(E) 텍스트/스캔 문서라 애초에 표(row)가 아니다**
- 아르헨 에너지부 월간 리포트, 페루 MINEM 볼레틴, 콩고 CTCPM·Gécamines
  보고서는 전부 PDF다. 그중 스캔 이미지(OCR 필요)로 확인된 것(아르헨 리포트,
  칠레 Sernageomin 97MB 파일)은 표 추출 자체가 별도 프로젝트급 작업이 되어,
  "수집 가능하지만 값이 얼마나 정확할지 보장 못 하는" 상태로 남는다.

**요약**: (A)(B)(C)는 "기술적으로 시계열을 만들 수는 있지만 만들면 정보가
왜곡되거나 구멍이 난다"는 뜻이고, (D)는 "그 나라 발표 자체가 없다"는 뜻,
(E)는 "표가 아니라 문서라서 추출부터 별도 공정이 필요하다"는 뜻이다. §4의
통계적 기각과 달리, 이 절의 항목들은 **애초에 R10 검정 테이블에 올릴 수조차
없었던** 항목들이다.

## 7. 키 발급 후속 반영 + GACC headless 시도 상세 (2026-07-29, 같은 날 후속)

§3의 #1~#3(BPS·Census·Comtrade)을 사용자가 당일 가입·발급했다. 결과 요약은
§1 총괄 표·§3에 반영했고, 여기서는 GACC headless 시도의 **기술적 상세**만
기록한다(상용 벤더 없이 접근 가능한지 실제로 판별하기 위한 최종 시도).

### 7-1. 시도 배경

§2-1에서 지목한 대로 GACC 상세 통계(니켈·코발트·리튬 포함 전체 HS 품목)는
`stats.customs.gov.cn`이 순수 HTTP 요청을 412+JSL(가속락) JS 쿠키 챌린지로
차단한다. 어제는 "(a) headless 브라우저로 우회 가능하나 취약"으로 적어뒀는데,
실제로 되는지 직접 검증했다.

### 7-2. 시도 5종과 결과

| # | 시도 | 방법 | 결과 |
|---|---|---|---|
| 1 | 기본 Playwright | headless Chromium, 실제 UA, `networkidle` 대기 | HTTP 412 → 챌린지 JS(`/Qy6JDI4LYvbD/*.js`) 로드 200, 쿠키 4개 발급(`AV7KYchI7HHaS/T`·`__jsluid_h`·`SF_cookie_251`) → 콘텐츠는 빈 페이지 |
| 2 | 응답 추적 + 명시적 재로드 | `page.reload()`로 챌린지 후 재요청 유도 | 자동 재탐색 발생 확인 — 최종 응답이 **400** |
| 3 | 개별 지문 은폐 | `navigator.webdriver`/languages/plugins/chrome.runtime/permissions.query init script 패치 + `--disable-blink-features=AutomationControlled` | webdriver 은폐 확인(`None`)됐지만 **412→200→400 결과가 바이트 단위로 동일** |
| 4 | `playwright-stealth`(표준 종합 은폐 라이브러리 v2.0.3) | 라이브러리 기본 evasion 세트 전체 적용 | webdriver=False 확인됐으나 **역시 동일한 412→200→400** |
| 5 | HTTPS(인증서 검증 무시) | `ignore_https_errors=True`로 `https://` 접근 | **HTTP와 전혀 다른 인프라**(Yunjiasu/云加速 CDN — 응답에 `browser.jpeg`·`node-yunaq.jpeg`·`line.jpeg`·`origin.jpeg` 요청경로 진단 이미지 포함)로 라우팅 → **504 오리진 서버 무응답**. 어제 실측한 "self-signed 인증서 체인 오류"의 실체가 이 CDN 자체의 구조적 문제였음이 드러남 |

400 응답의 헤더까지 확인: `x-via-jsl: c84a5e4,-`(JSL 프록시가 요청을
실제로 처리했다는 뜻)·`cache-control: no-store`·본문 없음 — 왜 막혔는지
진단 메시지조차 없다.

### 7-3. 결론

챌린지 스크립트 자체가 VM 바이트코드로 난독화된 상용 봇탐지 코드라 수동
역공학이 비현실적이고, **지문 스푸핑 수준의 대응(개별 패치·업계 표준
라이브러리 둘 다)으로는 뚫리지 않는다**는 것이 재현으로 확인됐다. HTTP
경로는 400, HTTPS 경로는 (다른 CDN을 거쳐) 504 — 서로 다른 이유로 막힌
두 경로 모두 막다른 길이다.

**판정 변경**: §1·§3의 "(a) headless 자체구축"을 "취약"에서 **"불가"로
하향**한다. 추가로 투입해도(더 정교한 스텔스 도구·프록시 로테이션 등)
성공을 보장할 수 없는 반면, 상용 벤더 구독(b)은 확실한 대체 경로다 —
**이 방향으로의 추가 투자는 재시도 금지, 협조 요청 범위를 니켈·코발트·
리튬 3광종으로 좁혀 유료 경로로 넘길 것을 권고**한다.

테스트 스크립트는 결론이 부정적이고 프로덕션 코드가 아니므로 저장소에는
커밋하지 않았다(세션 스크래치패드에만 보존).
