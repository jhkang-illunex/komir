## 무엇인가

report_gen 분석요약이 제공하는 10개 page_id 전부에 대해, 실제 KOMIS 데이터로 결과문을
직접 생성하고 발주처 2026-09-09 업무지시서(§2 공통원칙·§3.1~3.3 메뉴별 지시·§4 품질오류
체크리스트)를 항목별로 대조한 점검 보고서다. 사용자 요청: "지금 10개의 보고서를 작성하고
지시서에 있는 내용과의 준수 여부를 체크해주세요. 광물가격은 2024~2026년 데이터를
기반으로 하세요."

10개 page_id: `price_base_metals`·`price_minor_metals`·`price_iron_energy`·`price_other`
(§3.1) / `indicator_composite`·`indicator_market`·`indicator_supply`(§3.2) /
`map_korea`·`map_global`·`map_mineral`(§3.3).

## 실행 방법

`AnalysisSummaryService(None, llm=None)` 직접 생성 → `AnalysisSummaryRequest` 조립 →
`.analyze()` → `report_render.render_markdown_report()`(streamlit 데모가 내부적으로 쓰는
것과 동일한 계산·렌더링 경로, 스크린샷·수기 편집 없음). 광물자원가격 4종은 요청에
`start_date="2024-01-01"`을 넣어 필터링했다(철·금은 원본 실측 캡처가 이미 2024-01-02
~2026-08-27이라 별도 필터 불필요). 나머지 6종은 발주처가 제공한 실 KOMIS 덤프를 그대로
`komis_response`(또는 `komis_snapshot_response`)로 넘겨 조회 시점 그대로 썼다(별도 기간
지정 없음 — 데이터 자체가 해당 페이지의 조회 단위(연·월)를 이미 담고 있음).

## 발견한 미해결·구조적 한계 (재확인, 신규 아님 — 사용자 기결정 사항)

- **§3.2 3건**(5·6·7행의 ⚠️): 개별 광종 가격(composite)·하위요인(market)·2개 요인(supply)
  데이터가 요청 JSON 모델 자체에 없어 계산 불가 — **"이 리포트 요약은 JSON으로 제공되지
  않은 데이터는 연동하지 않는다"는 사용자 확정 원칙(2026-09-09)에 따라 신규 KOMIS
  엔드포인트 연동을 진행하지 않기로 확정**. 코드 버그가 아니라 설계상 범위 밖이다.
- **§4-6 map_korea/map_global "기준일 표기"**(8·9행): report_gen은 KOMIS 응답이 준
  `srchDateE`(조회 파라미터 echo)를 그대로 쓸 뿐이라, 실제 조회 시 어떤 날짜를 넣었는지에
  좌우된다 — streamlit_demo(UI) 쪽에서 사용자가 선택한 연도와 실제로 KOMIS에 보내는
  날짜가 다르면 이 화면에도 그대로 나타난다. report_gen 코드 안에서는 재현·수정 대상을
  찾지 못했다(이전 §3.3 점검에서도 동일 결론).
