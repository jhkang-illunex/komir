## 정정(같은 날, 사용자 지적) — 슬라이드 스크립트의 문자열 패턴매칭 제거

"수정한게 report 만드는 루틴이지? 슬라이드는 계속 말하지만 복붙만
해야 해 수정 전부다 리포트 요약 api에서 작성 되야 해" — 직전에 고친
"한국 관련 루트"/"연도별 변화" 절 배치 버그는 **report_gen API가 아니라
이 슬라이드 빌드 스크립트의 버그**였다(API 응답은 처음부터 정확했다).
다만 그 버그의 근본 원인은 스크립트가 report_gen 응답 문장을 문자열
패턴("대한민국이 포함된 교역 루트" 부분일치, "최근 N개년…추이는" 등)
으로 다시 추측해 절을 나누고 있었기 때문 — report_gen 응답은 이미
문장마다 `evidence_ids`(claim id, 예: `korea_route_rank`·
`route_yearly_trend`·`trade_scale_trend`·`cross_measure_comparison`)
를 붙여 주는데 그걸 안 쓰고 있었다.

**조치**: `claims_by_id()` 헬퍼를 추가해 모든 절 배치를 claim id 기준
으로 바꿨다(map_korea·map_global·map_mineral 3개 함수) — 문자열을
다시 해석하는 코드를 전부 제거했다. 이번 정정으로 슬라이드 내용
자체는 안 바뀌었다(같은 문장이 같은 절에 들어감, id 기준으로 찾아도
결과가 같다는 걸 재확인) — 다만 report_gen이 향후 문구를 조금만
바꿔도 슬라이드 배치가 깨지지 않도록 견고해졌다.

## 정정 2(같은 날, 사용자 지적) — 광물자원가격 4종 기준일이 메뉴마다 제각각이었다

"광물가격지표에서 보니깐 메뉴 마다 기준일이 다르네요 다 오늘 조회힌거

재사용하고 있었다 — "오늘 조회"가 아니었다.

**조치**: 4종 전부 komis.or.kr에서 직접 라이브 재조회
(`komis_fetch.fetch_price_*`, `compare_mineral_code` 파라미터로 비교
광종까지 한 번에) — 비철금속·희소금속·기타 3종은 2026-09-10(가장 최근

이건 버그가 아니라 그 가격기준(price_criterion) 자체가 KOMIS에서 그
주기로만 갱신되는 실제 특성으로 보인다(재조회해도 동일 날짜 재확인) —
날짜를 억지로 맞추지 않고 실측값 그대로 반영했다.

희소금속(코발트) 재조회 중 가격기준이 이전 세션의 정적 덤프(Cobalt

`getMnrlPriceCrtr`가 특정 기준을 지정하지 않으면 그때그때 다른 후보를
고를 수 있어 보이며, 둘 다 KOMIS가 실제로 제공하는 정당한 가격기준
이다(허위 데이터 아님). 이번엔 LME CASH로 통일(비철금속의 동도 LME
CASH라 오히려 더 일관적).
