# 광물자원가격 — 여러 광종 + 비교광종 확인 (2026-09-13)

> 배경: "광물 자원 가격에 여러 광종 및 비교 광종 까지 같이 부여해서 다시
> 한번 검증해봐주세요." — 광물자원가격 4메뉴(price_base_metals/minor_metals/
> iron_energy/other) 각각에 서로 다른 두 광종(주계열+비교광종) 조합 3~4개씩,
> 총 13건을 배포된 실 컨테이너에 `POST /api/v1/analysis/prices/...`로
> 호출했다. 재현: `compare_mineral_check.py`.

## 왜 합성 데이터를 썼는지

8개 정적 KOMIS 덤프를 전수 확인한 결과 `compareMnrl`(비교광종 응답)이
실제로 채워진 캡처가 **하나도 없었다**(KOMIS 화면에서 비교광종을 선택한
채로 수집된 적이 없었던 것으로 보임). 그래서 서로 다른 두 광종의 단일계열
응답을 KOMIS가 실제로 주는 것과 같은 모양(`data.defaultMnrl`=주계열,
`data.compareMnrl`=비교계열, `dataAvg.cmpMap.INFO`=비교광종 이름·가격기준)
으로 합성했다 — `input_data.py::_parse_komis_price_response`의 문서화된
파싱 규칙에 맞춘 입력을 만든 것이지, 그 파싱 코드 자체를 재사용하진
않았다(교차검산 원칙 유지).

- **헤더 자동 채움**: 요청 바디에 `compare_price_criterion`을 명시하지
  않았는데도(비교광종 이름만 지정) 보고서 헤더에 "비교광종 가격기준"이
  자동으로 채워졌다 — `dataAvg.cmpMap.INFO.prcCrtr` 자동 인식(2026-08-30
  기존 구현)이 새 조합들에서도 정상 동작함을 재확인.
- **상대가치(가격비율) 문장**: 관측일이 충분히 겹치는 조합(예: 텅스텐/
  몰리브덴, 흑연/금)에서 "OO/XX 가격비율은 현재 …, 조회기간 평균 대비
  …% 높은/낮은 수준입니다" 문장이 정상적으로 추가됨을 확인 — 다만 이
  비율 자체의 정확한 산식 재검증(독립 재계산)은 이번 확인 범위 밖(기존
  "통계 심화층" 스코프와 동일한 이유로 제외, `report_gen_풀검증_보고서_
  260913.md`의 "검증 범위 밖" 절 참고).
- INTERNAL_ERROR·NO_DATA 0건 — 13건 전부 정상 처리.
